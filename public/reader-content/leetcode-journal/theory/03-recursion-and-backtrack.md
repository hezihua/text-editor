## 递归三件套

1. **终止**：空节点、空区间、规模小到能直接算
2. **子问题**：规模严格变小，且和原问题同构
3. **组合**：用子结果拼出当前结果

树题几乎都是这个模板。

```go
func maxDepth(root *TreeNode) int {
    if root == nil {
        return 0
    }
    return 1 + max(maxDepth(root.Left), maxDepth(root.Right))
}
```

[109 有序链表转 BST](/topics/linked-list/convert-sorted-list-to-bst) 是「找中点当根，左右半段再递归」。中点把规模折半，天然平衡。

## 分治

把问题切成几块（尽量不重叠），分别解决再合并。归并排序、快速选择、[23 合并 K 条链](/topics/linked-list/merge-k-sorted-lists) 的两两合并，都是这个节奏。

主定理粗看：每层做 $O(n)$，切成两半，深度 $\log n$，总时间 $O(n\log n)$。快排最坏总切出 $1$ 和 $n-1$，深度变成 $n$，退化成 $O(n^2)$。

## 回溯

搜索树：做选择 → 递归 → **撤销**。漏撤销会脏状态。

| | 分治 | 回溯 |
|--|------|------|
| 目标 | 一个组合答案 | 所有合法方案 |
| 子问题 | 通常不重叠 | 分叉后回头 |
| 现场 | 切区间 / 切链表 | 改数组再恢复 |

全排列、组合总和、N 皇后是标准回溯。能剪枝就剪：当前和已经超标、剩余长度不够，直接 return。

## 记忆化

重叠子问题如果每次重算，递归树是指数。加一张表（或 DP 数组）后，每个状态算一次。斐波那契、爬楼梯、路径计数都是「递归 + 记忆化 = DP」。

## 坑

- 没有缩小规模 → 死递归
- 链表切分时中点左右边界含糊 → 漏节点或重复
- 回溯里切片是引用，存答案要拷贝一份
