> **课程来源**：FDE 实战训练营第一期 · 第 04 节
> **时长**：约 1 小时 30 分
> **用途**：做方案前先看懂对方公司怎么活着

> **先抓主线**：做企业 AI 项目，不要从“全公司上什么工具”开始。先找有价值的问题和能拍板的人，再看流程涉及哪些部门，最后判断从个人试用、部门协作还是组织机制切入。个人提效是起点，不自动等于组织提效。

## 一、为什么要讲组织

给客户出 AI 方案，先要懂架构、流程和经营逻辑，才能判断真实需求和痛点。否则只会套模板、堆名词，客户不买单。

这节课临上场又改过课件。当天下午还在跟宁波一家上市公司沟通：集团 1000 多人，飞书重点用户，内部已上 Codex，n8n / 扣子做过，老板把一把手工程做得很好，还搞黑客松，员工不抵触甚至喜欢 AI。卡点不再是「会不会用」，而是：

> 怎么从个人提效到组织提效。

有人用得好、有人用不好；用得好的又各有各的想法。大厂往往不接这种单——要长期陪跑，一个一个拆工作流和业务逻辑。所以这节在「不同公司怎么运转」之外，加了「个人 → 组织」这一块。

## 二、三种体量，先找拍板人

把公司看成**商业生命体**，它是长出来的，不是一天设计出来的：

```
一人闭环（OPC） → 小公司（老板中心） → 中型公司（业务中心） → 大型集团（总部 + 复杂前中后台）
```

| 体量 | 运转逻辑 | 成交关键 | 高价值问题 |
| --- | --- | --- | --- |
| **小公司** | 老板说了算，快，但老板是瓶颈 | 搞定老板 | 解放老板的时间、注意力、决策，做**老板辅助系统** |
| **中型（约 50 人以上）** | 职能部门 + 事业部，业务部门扛收入和利润 | 也可搞定老板，更要搞定**业务负责人**，再协同财务 / 人事 / IT | **增长和赚钱** |
| **大型集团** | 总部 + 各地区业务单元，流程极复杂 | 搞定能给钱、能开内部通道的高层 | 生存发展往往没大问题，怕的是**组织老化、跟不上时代** |

> 拍板人能给钱，能保证这个方案推下去。他支持，其他人都不会有太大的意见或者阻挠。

**拍板人**就是上面这句话：能给钱，并能保证方案和项目推下去。AI 落地首先是一门生意，所以只做两件事：

1. 找到能成交的人（拍板决策人）
2. 找到公司里离钱近、有价值的问题

## 三、生命体怎么长大

**OPC（一人公司）** 也是组织。一个人要从获客、成交、交付到回款闭环，必须把自己变成六边形战士、时间拉满，才能在市场上活下来。

**小公司 / 老板中心制**：少数员工围着老板转——销售商务、运营、交付、讲师。高效、变现快、适应市场，但老板就是瓶颈。IP / 博主获客尤其明显：商业模式绑在老板身上。客户会问「到底谁来交付」；不是本人交付，就觉得没那么值钱。讲师自己的公司也是如此：本人承担大额现金流，也成为团队瓶颈。你要同时承认这个瓶颈，用 AI 解放老板，并慢慢培养内部讲师和交付。

**中型公司**：人数大约 50 人往上，出现分公司 / 事业部。一块是后端职能部门，一块是出去跑客户的事业部门。

**大型集团**：拆简单就是总部 + 各地区业务单元。总部课上归纳管四件事：

1. **战略**：往哪发展
2. **规章制度**：怎么管理
3. **资金**：商业生命体的血液，总部是心脏，泵血必须经过总部
4. **风控**：合规、法务、财税——底下的人只管自己赚钱

## 四、需求只分两类：内部经营 vs 外部增长

今年做过的客户，需求收成两大类。

| | 内部经营 | 外部增长 |
| --- | --- | --- |
| 本质 | 从他口袋里掏已经在的钱（降本增效） | 帮他赚钱，再分一笔 |
| 验收 | 各部门各公司标准极不统一（例如法务看卷宗是更快还是更准） | 相对统一：获客数、成交、升单、复购、转介绍 |
| 上限 | 做到 30%～50% 已经非常了不起 | 想象 10 倍、100 倍，分二三成甚至一半都谈得拢 |
| 难度 | 繁杂、周期长、成本高 | 更难做，但更好分钱 |

增长链路：

```
获客 → 销转 → 升单 → 复购 → 转介绍
```

一个大概适配（不是绝对）：

- **前台做增长**：多获了多少客户、多赚了多少钱。解法可以是自媒体、GEO、线下渠道、短视频直播代运营——关键是起效果、能溯源
- **中台做提效**：时间、速度、质量；多接了多少客户、多做了多少产品
- **后台做降本**：少花一点钱

课上广东会销案例：一家做中老年生意约 17 年的集团，肇庆一带每个地方十几二十家门店，几乎每天三场课，一场 100 多人，外面像小卖部，拉开推拉门里面是带电流的「治疗椅」。获客极强，新客可能占 1/3 到一半，**销转转化率非常低**。切入点就不是再获客，而是傻瓜式销转：给店长出专业方案、日常维系、提升销售能力。升单要可视化，让人看得见效果；转介绍更多是政策返点，AI 能介入的没那么多。

和大树 AI 圈的大树老师当面聊过同一判断：现在多数落地服务商做降本增效，又苦又累、钱少、客户评价不高；**只有外部增长能赚到更多钱**。团队也在把产品往增长上转。

「要不要做成系统？」获客已经有内容生产系统、AI 中台营销系统等竞品。本质仍是 **Agent + 知识库 + Skill**，把 AKA 封装得更可视化。同样一份库，目录看起来没意思，脑图像神经元延伸，老板就觉得特别——人是视觉动物。GEO 同行用饼图看板展示「多少来自豆包、多少来自 DeepSeek」，也好演示。

## 五、前台、中台、后台（课上自己的划分）

这套划分是团队实践出来的，课上说不一定等同于市面某一流派，但对齐客户沟通够用。

```
前台（搞钱）     市场品牌 → 销售商务 → 客户成功 / 售后
中台（创造价值） 产品（决定做什么）→ 交付 / 研发 / 授课 → 运营 → 项目
后台（活下去）   财务 · 人力 · 法务 · IT · 行政
```

**前台**离钱近：

- 市场和品牌（含 IP 助理）：让人知道你、信任你
- 销售和商务：把上门的客户谈下来，也可能做渠道和线下获客
- 客户成功 / 客户服务：复购和转介绍，偏售后

前台解决「客户进来、钱进来」，不回答「为什么找你买单、买的是什么」——那是中台的事。

**中台**创造价值：

- **产品**：决定做什么产品、什么功能（战略仍归老板 / 高层）。AI 来了，产品经理手里有 Codex / Claude CLI，自己也能搞研发，但逻辑上产品和开发仍应分开理解
- **交付**：研发、讲课、服务、咨询方案——把东西做出来
- **运营**：让业务持续转、收反馈、迭代；含客服、私域、客户运营
- **项目**：进度、质量、验收。公司体量大了，总得有人管「给客户服务得怎么样」

**后台**让公司持续活下去，大小公司都是这五块：

| 部门 | 核心 |
| --- | --- |
| 财务 | 管钱和财税风险。少几十万有时还能补；少一个小数点，会计要翻箱倒柜找那一分钱，因为可能意味着老板进去 |
| 人力 | 找人、用人、培养、激励、淘汰 |
| 法务 | 合规和风险。小公司外请顾问（课上请的团队也给影视旭丰做股权架构）；大公司内部法务常被嫌卡审核，但又必须在 |
| IT | 系统、数据库、账号 |
| 行政 | 脏活累活：保洁、保安、物资、桌椅、前台接待 |

## 六、个人提效：先解决用上、用好、不抵触

不可能上来就让整个组织提效。个人提效三步，对应人的三个原罪：

这里的“用上、用好、不抵触”不是三堂培训课，而是采用过程里的三个障碍：员工有没有工具和机会开始、能不能用它完成真实任务、是否相信采用后不会给自己带来不合理风险。FDE 可以通过培训和带练解决一部分问题，但激励、工作量和岗位安排需要客户管理层作决定。

| 步骤 | 目标 | 怎么做 |
| --- | --- | --- |
| 1 | **用上** | 手机里先装 WorkBuddy，加上入门培训，拉齐认知。否则永远觉得和网页版豆包、DeepSeek 没区别 |
| 2 | **用好** | 培训 + 带练 + 轻度定制（简单知识库和 Skill），做一个小智能体解决一个业务问题 |
| 3 | **不抵触** | 一把手工程。老板和高层明确：不是为了裁你，是提效、避免被对手淘汰；认可、激励、内部黑客松发奖金 |

有人用 Codex 处理完工作文件再假装上班摸鱼——你要蒸馏，他反蒸馏。抵触是自我保护：怕用了有不好的后果。物质不匮乏的 90 后、00 后更要精神认可和宽松一点的成长空间。文化、制度、激励，外部服务商给不了，只能给建议；**只有老板带头才搞得动**。课上见到的先进公司，内部 AI 活动经常满人。

## 七、部门提效：共享上下文、共用能力、共同标准

个人强了，部门仍可能是一盘散沙——水平不一，用得好的各有各的想法。三件事：

从个人到部门，关键变化是把“某个人的技巧”变成团队可复用的能力：资料能共享、常用 Skill 或流程有维护人、产出有基本标准。否则个人做得再快，经验也容易留在自己的电脑里，其他人无法接手。

1. **共享上下文**：部门知识库，项目、客户、进度不能各放各的电脑。不共享，每次靠「再去一嘴」，部门提效是假的。指定一个 **AI 先锋 / AI 苗子** 管理，或部门老大指定专人
2. **共用能力**：同一水平的知识库、Skill、定时任务、项目协作。像插件、U 盘，即插即用，不必每人从零搭、也不必先懂原理
3. **共同标准**：统一工具栈（要用 Obsidian 都用 Obsidian，不要一人飞书一人钉钉）；不要还在写超长重复提示词，却不用 Skill

真实客户：培训从提示词、n8n / 扣子做到 Skill / 智能体，WorkBuddy 官方、飞书官方都去部署过，1000 多人的 AI 化却扛在 **IT 部门十几个人**身上——线上会里 IT 挂着几乎不说话。不能把全公司压在一个部门。课上叫**撒豆成兵、星星之火**：每个部门先长出一两个代表，再渗透到全部门。服务商也不可能派 100 人处理 1000 人的问题，客户也养不起。商业生命体变复杂之后，不能一刀切。

项目制培训就是为此设计：从各部门筛先锋，让能力长在客户身上。

## 八、组织提效：人才、工具、组织必须一起升级

> 人才加工具、加组织，三个东西要同时做升级。但凡其中一个掉队了，都不太可能实现公司整体的组织升级。

三层里掉一层，整体升级都难。

可以把前面三层连起来看：个人愿意并能够使用，部门把有效做法沉淀并共享，公司再为权限、流程、责任和资源做调整。组织升级不是把更多 Agent 发给员工，而是让有效做法能够跨人、跨团队持续运行。

### 1. 人才

技能在换：手写速记员被键盘快的人淘汰，键盘快的人被语音输入淘汰。思维也在换：还靠线下攀关系、送礼，会被把 IP 做起来的人降维打击。市面上没有足够的人。FDE 做得不好是成本，做得好要么单干、要么被挖（课上随口：I tag 给 20 万一个月，别人给 30 万）。这个市场三样稀缺：

- **客户**：自媒体或稳定渠道都能解
- **钱**：重服务没现金流人就走，甚至举报；投融资市场不缺钱，缺好项目
- **人**：最难。听完课会有启发，跟着实操能大概学会，仍不敢打包票马上服务大客户。人才是不断遇到问题、解决问题长出来的

做 FDE 训练营的目标，是聚集优质落地人才：头部只跟头部合作，客户和同行招不到人，只能来找你。项目里把人带起来，自己不必全养着，筛选后推给企业，对方把待遇给足。

### 2. 工具

组织层只认一个方向：**企业级 Agent**。Codex、WorkBuddy 个人版都还是个人工具。WorkBuddy 一个账号常只能装在一台电脑、连一个手机 App / 小程序，部门多人同时用就连不上。企业版接了代理，课上仍说还不够完善。千问办公、钉钉改名传闻，都在抢办公 Agent，做得稍好的仍是 WorkBuddy，也没好到够用。

合作伙伴的思路更绕一层：不跟 WorkBuddy / Codex 竞争，而是在它们上面套壳。模型和大厂应用升级，对套壳反而是助力。大厂选造车（工具好复制、上限高），FDE 选培养司机。

部门提效里的「部门知识库 + 共用 Skill + 共同标准」，封装进一个办公企业级 Agent，就不必每个部门再造轮子。

### 3. 组织

现在多数组织仍是**科层制 + 契约**。科层来自军队：一个人管理半径最多 7～10 人，所以有十夫长、百夫长；韩信点兵多多益善，是因为把活一层层分下去。契约来自自由市场：没有合同，就有人睡到下午 4 点不回消息，或谈好五五分、分钱时改三七。劳动合同是买断时间的卖身契，降低找人的交易成本。

AI 时代的变化：人和人协作可能变成新摩擦。跟 Agent 聊清楚、出了方案，再开两三个小时会，下属复述得好像懂了，交回来一坨屎——不如直接派给 Agent。于是出现**项目制**：人人都是项目经理，一言堂，自负风险收益，主观能动性被激发。课上原话：不要看网上讲民主，民主一定导致各自站在利益上扯皮，项目里需要一个说了算的人。

但科层和契约不会彻底消失。它们脱胎于人的弱点（贪婪、懒惰等）。张笑宇老师那本书里：AI 可替代脑力和体力，替代不了**政治（你死我活）**。至少 100 年内，人类仍是社会运转的底层代码。投资人吹 14、15 岁少年每天睡三四小时 Vibe Coding 代表未来，课上反问：持续一个月试试。

变化后的图景：中后台（人力、法务、运维）仍在，因为是社会制度的根本；上面不再一层层叠，而是很多项目组去战斗。

```
人才更新（技能 + 思维）
        +
企业级 Agent（统一上下文 / Skill / 标准）
        +
项目制战斗 + 中后台托底
        =  组织提效的较大概率
```

## 九、课上案例：不同行业怎么下手

**医美 / 电商 vs 工厂。** 部门分工跟业务走。医美围着高客单客户：销转、素品、自媒体（还要注意合规）、门店、招商加盟，水下生意多。制造业常拆成工厂流水线和文职（市场、采购、客户、有的也做自媒体）。流水线已经是精密工业流程，几乎很难用 AI 再提效；能做的是办公室里手敲电脑的那一段。制造业非常需要 **AI 原生 ERP**，金蝶用友加了 AI 也不好用；一旦好用，一年几千万。但极难：附近利尔达产业园，创始人说研发从四五十人用上 WorkBuddy / Claude Code / Codex 后砍到 16 人，16 人开发 3 个月，仍没有做出 AI ERP 雏形。

**内部经营怎么定价。** 两个口径：先有底价——至少一个智能体（知识库 + Skill）解决一个核心问题，起步约 **1 万**，再看复杂度；然后再算节省的时间（换算人力）或带来的客户，作为额外收益。

**外部增长怎么打。** 获客本质是内容生产工具。团队做的不是批量 60 分（那更像 GEO），而是每天两三篇七八十分：公众号、小红书图文，尽量不露脸。数字人效果差，基本不做；要视频就写脚本，前提是有人表现力够。定价：安装部署 **2 万起**，小红书再单独约 1 万，按种草 / 宣传 / 单款卖点可视化加定制。B 端更适合公众号（老板看文字、微信好转发），不一定硬做小红书。海外电商用 AI 生成 15 秒产品展示再投流，只要生成 + 投流的 ROI 算得回来，完全愿意多投 100 条。MCN 美妆如果走量 + 投流，AI 视频合适；高客单精致生活，不能什么都上 AI。

**饲料类准上市工厂：销售几百、财务 60、公司上千。** 先问老板要什么，不要上来整体转型。利润很低、获客靠线下拜访时，可能先看降本。财务里发票录入、检查可以让 AI 做，记账、对账、报税砍不掉；60 人收到 10 人太吓人，收到二三十已经很可以。信息不够就不要硬出方案，回群里把需求聊清楚。

**数字化还没完成，同时上 AI？** 先让 AI 清洗手头的 PPT / Excel / Word，存进知识库和数据库。采购现成 ERP 只符合需求 60%、但支持二开：用 Codex 按需求魔改，仍要工程师做架构和 PRD、反复测后端，不要纯靠 Vibe Coding。不能二开就先用着，一边自建或找更好的，替换要走内部采购标准。封装一个「智能体」快的一晚上，慢的一周多；真去做 Agent 产品则难得多。

## 十、踩坑

- 没找到拍板人就铺方案，IT 热、业务不给钱、项目推不下去
- 小公司不解放老板，却去做很重的全员系统
- 中型公司绕过业务负责人，直接找职能部门磕
- 大集团只讲增长话术，对方真正怕的是组织老化
- 个人都没用上，就要组织提效
- 先进公司已经上了 Codex，还在重复讲提示词入门
- 把全公司 AI 压在一个 IT 部门十几个人身上
- 工厂流水线承诺 AI 提效；文职和 ERP 才是可谈的切口
- 内部经营按「省了多少时间」细算时薪，客户觉得没必要，自己也算不清楚

## 十一、这节课可以做的事

- [ ] 画出客户是 OPC、小公司、中型还是大型集团，并写出拍板人姓名 / 角色
- [ ] 用前台、中台、后台把部门归堆，标出离钱最近的一段流程
- [ ] 和客户明确：这次买的是内部经营还是外部增长，验收指标各写三条
- [ ] 个人层先检查：装上没有、培训带练有没有、老板有没有公开站台
- [ ] 部门层检查：有没有共享库、共用 Skill、统一工具和指定的 AI 先锋
- [ ] 组织层不要只卖课或只卖工具，人才、企业级 Agent、项目制要一起谈
- [ ] 选一个最小单元（一个业务问题或一个部门），不要一上来「全公司转型」
- [ ] 内部经营先报智能体底价，增长先报部署费，再谈分成或加项

下一节拆商业模式：获客、销转、交付，以及找到水源之后怎么挖水井、铺水管、收水费。把组织诊断和赚钱逻辑接上，才能写出不空的 AI 改造提纲。
