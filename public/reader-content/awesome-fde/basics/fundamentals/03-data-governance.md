## 一、为什么先做 K

AKA 里，Agent 是能干活的 AI，Automation 是自动处理。第三节只讲 **K：Knowledge Base and Database**（第二节已说明 K 为何是「途经点」，本节不再重复框架，只讲治理与落地）。

> 自动化建立在知识库和数据库比较清晰完整的基础上。你都不知道工作 1、2、3 步怎么做、公司资料在哪，怎么让 AI 替你干活？

Agent 课上劝大家不要碰自建：1:1 复刻 WorkBuddy / Codex，难的不是 UI，是后端数据、知识处理和工作流稳定性。客户一定会问「跟我自己用 WorkBuddy 有什么区别」。当天上午在阿里滨江园区（阿里国际和 1688；其他部门已迁西溪），1688 的 FDE 在推牛顿助手；阿里国际站在推 **Axlework**（去年 25 年七八月已推，界面有点抄 Manus）。对方把 Agent 分成四类：

| 类型 | 例子 | 课上判断 |
| --- | --- | --- |
| Coding Agent | Claude Code、Trae | 窄，大厂大集团才大批采购 |
| 通用办公 Agent | Codex、WorkBuddy、Coworker、Trae Solo / Trae Work | **国内办公 Agent 毫无疑问 WorkBuddy 胜出** |
| 垂类 Agent | 贸易向的 Axlework | 你能做的顶天是垂类，客户还是会问跟 WorkBuddy 有何区别 |
| 个人 Agent | 豆包 | 个人娱乐 |

自动化在知识库创建之前做不了。数据库是为了让知识库发挥更大作用；今天重点仍是知识库。

## 二、不要收藏夹，要可信上下文

新手最容易把知识库当收藏夹，疯狂丢链接。自媒体「收藏进收藏夹吃灰」对应人的囤积癖：担心没有吃的就囤，囤完感觉安全。库越大越杂，检索越慢、噪声越多，真正有用的上下文更难找。

> 我们需要的不是大而杂、大而全的上下文，我们需要的叫可信上下文。

筛知识和筛人一样：一开始不严，后面全是麻烦。

## 三、优质上下文的四个标准

| 标准 | 要求 | 怎么落地 |
| --- | --- | --- |
| **可追溯** | 来源网站、链接、书、段落、作者、时间；自媒体还可记点赞、收藏 | 存的时候就打来源标签；做成**知识库管理 Skill**，换电脑一起迁走 |
| **可理解** | 完整（有前因有后果）；不重复；无矛盾冲突 | 结款约定五五分、真结款只给四成还说 10% 是成本——没有单一标准就不可理解 |
| **可控制** | 权限：管理 / 编辑 / 阅读 / 不可见 | 老板、助理、实习生、保洁看到的不该一样 |
| **可相信** | 来源权威：官网、行业、专家；每家公司细则不同，但必须有「优质」标准 | 从入口就把垃圾挡在外面，少做事后清洗 |

## 四、数据 → 信息 → 知识 → 智慧

```
信号 / 原始数据  →  信息（发生了什么）  →  知识（规则、规律、经验）  →  智慧（判断力）
```

早年很多 AI 博主是信息差博主：把推特搬到国内，你只知道发生了什么。从信息里抽出规则、规律、经验，才叫知识。大量规则还在老员工脑子里，必须访谈、录音、梳理，才能进库。只堆官网 PDF，库是空的。

知识库两个作用：

1. 让 AI **执行**：公司怎么运转、业务 1、2、3 步怎么走
2. 更核心：辅助人 **判断**（智慧）

所以知识库和数据库要一起做：文本回答流程、步骤、判断标准；关系回答谁和谁有关、什么状态、什么日期。

## 五、知识库 vs 数据库

文本只能从上到下排，索引能力有限。多维表格能把结构摊开。

课上用飞书「选题管理系统」演示一张表可以同时有：

- 发布日期、紧急程度、内容进度（选题池 / 大纲 / 修改 / 发布 / 作废）
- 选题类型（盘点 / 热点 / 保姆式教程 / 思考洞察 / 科普 / 创意 / 营销）
- 难度周期、目标受众、内容目的（曝光 / 信任 / 转化 / 私域 / 变现）、所属专题

字段类型包括单选、多选、文本、人员、日期、附件、数字。这是普通 Excel 不好做的。中小公司多数用飞书多维表格、企微智能表格就够，不必先上工程级数据库。

> 知识库给「怎么想」，数据库给「现在是什么状态」。一个实习生读过制度、员工手册、岗位 SOP 和要用的数据，一定比一无所知干得好。这个就叫上下文。

实际判断时，可以这样分：制度、SOP、产品说明、经验做法等相对稳定的内容，适合放知识库；客户当前进度、订单状态、日期、金额、负责人等会变化且需要准确查询的内容，适合结构化记录在数据库或业务系统里。两类信息经常要一起给 Agent：只读知识库，它可能知道流程却不知道这笔订单现在到哪一步；只读数据库，它看到字段却不懂业务规则。

## 六、中小公司轻量治理：六步怎么做

大多数公司连知识库都没有，不必先谈本体论。课上给的是非常小白的顺序：

六步的顺序有原因：**先定用途，避免无目的堆资料；再盘点、筛选、补缺，保证内容可信；最后才清洗、入库并做具体应用。**每一步都要留下资料负责人和更新方式，否则知识库上线后很快会过期。

1. **先问目的**：这库要解决什么业务问题？不要为了囤积感而搭
2. **盘现有**：把手头知识和数据先堆到一起
3. **筛垃圾**：让 WorkBuddy / Codex 先列清单，或人脑找（低效）
4. **补缺口**：缺的 SOP 约业务人员访谈；补不了就标出来以后补。完整是优质上下文的核心标准之一
5. **清洗**：不必神话「切割治理」。Skill 市场搜微软开源的 **MarkItDown**，或自己搓清洗 Skill。重复、规则明确的事让 AI 做，**人做验收**
6. **入库 + 按场景搓 Skill**：库不是终点。有脸模库就做封面 Skill；有法规、判决、合同模板、律所观点、监管口径、竞对调研，就做法务顾问 Skill

进阶：接飞书 / 企微 / 钉钉 / 微信机器人，电脑 24 小时不断电断网，出门用手机下指令，整理好的课件以文件形式丢回飞书。

个人文档不超过 1 万篇（最多不超过 2 万）时，Obsidian 又轻又够用。讲师自己已快 5 万篇、远程仓库约 6GB / 10GB，开始考虑迁移或上 RAG；课上判断：**不超过 10 万篇其实没必要做 RAG**。断点、孤岛可以存在——公司管理不必跟公众号语料硬串；关键词搜得到就行。

## 七、技术地图（先认门牌，不必自己造引擎）

从浅到深，基础课只要求能跟客户解释「有这些技术」，实际用工具自带能力：

| 层级 | 是什么 | 课上怎么讲 |
| --- | --- | --- |
| **Markdown + Wiki link** | 井号标题、加粗；双向链接跳到另一篇 | 卡帕西（Andrej Karpathy，课上音近 Andrew Kapathy）推过的 LM Wiki，并不复杂。图片也能被 MD 索引 |
| **关键词检索** | 搜「曲率」拉出上万条 | Claude Code 用的就是这个，**没有用 RAG** |
| **RAG** | 检索 → 把问题和相关上下文一起给 LLM → 生成 | 「翻书找看起来像的段落」；业内也有「RAG 已死」的说法，因为它不够准 |
| **知识图谱** | 公司—员工—合同—产品—客户—会议的网状关系 | 像多维表格把维度串起来 |
| **GraphRAG** | RAG + 图谱 | 课上说约 24 年谷歌或微软开源；「织一张蜘蛛网，沿着蛛网找猎物」，能做跨文档关联和全局总结。成本高、时间长，一处错误容易连锁 |
| **本体论 / Ontology** | 把公司知识之间的关系讲清楚 | 大多数中小公司用不上，也没有周期和预算 |

搭建方法课上数了 8 种，覆盖市面大多数库：

1. **目录层级**：文件夹一层套一层
2. **分类**：讲师自己的四区——**原料区 / AI 总结区 / 人类消化区 / 输出区**
3. **标签**（tag）
4. **元数据**：title、source、podcast、episode、speaker、date、时长、URL
5. **Wiki 链接 / URL**
6. **MOC**：地图式索引，例如监控国内各大 AI 博主公众号的索引
7. **原子卡片**：Flomo 那种碎片先存、以后再整理
8. **知识图谱 / 本体论**：用得真不多

原料区要完整保留原文，因为幻觉很难百分百避免，随时要回到证据。AI 总结是二手信息，有必要，但不能纯吃「AI 给的屎」；有时间仍要看一手。讲师会把超长英文视频丢给模型，用自己的文风 Skill 做成图文并茂的大白话。消化区才有创业日记、战略决策；输出区（公众号、演讲、方案、朋友圈）凝聚审美和价值观，最适合从中提炼 Skill。

封面 Skill 是课上的具体玩法：把正脸、侧脸、3D 头模、五视图做成 MD 索引，加上画风、构图、爆款方法论；每次生成三个封面再选。最近用过的「揭秘企业 AI 服务万亿级市场信息差」「老板斩杀线」都来自这套，不必为封面单独拍照。

法务顾问库是另一条完整链路：先分别让 Claude Code、网页 Claude、网页 GPT、Codex 做深度调研并整合；再去官方法规库扒文书，去文书网存判决，把服务合同、劳动合同、合作协议、独家协议模板入库；再收权威律所观点、监管口径，以及市面法律 AI 平台竞对。有了这些信息源，再搓一堆法务 Skill。日常调用可以极短：「我现在要一个封面，标题如下」——模型自己拆关键词、找张力、提高点击。库是原料，Skill 才是入口。

## 八、知识库管理 Skill：库大了以后靠什么管

人看不过来时，做一套管理 Skill，核心几件事：

| 动作 | 课上做法 |
| --- | --- |
| **定时更新** | 每天凌晨 3 点，用飞书 CLI 以用户身份把最新飞书妙记存进原料区，并按客户沟通 / 合作渠道 / 内部团队分类 |
| **记 log** | 何时、存了什么、存在哪；有的在进化日志，有的在 JSON |
| **备份** | 飞书知识库一份；Obsidian 官方远程仓库（亚洲，官方也没访问权限，月费最多约 8 刀）；也可以 Git。NAS 更进阶，现阶段远程仓 + 飞书够用 |
| **版本** | V1 / V2 分开存，不要只留一份「最新」 |
| **防误删** | GPT 5.6 喜欢删东西。设 **hook** 拦截 `rm -rf` 一类彻底删除，先列清单问人，不要擅作主张。不会设就用自然语言让 Codex / WorkBuddy 写钩子 |

## 九、工具怎么选

| 场景 | 课上选择 | 注意 |
| --- | --- | --- |
| 个人 / 老板一把手工程 | **Obsidian**（Markdown + Wiki） | 难协作；本地快 |
| 团队 | **飞书云文档 + 知识库 + 多维表格** | 权限极细：查看 / 复制 / 创建副本 / 评论；表格很早就有自动化（定时把表发到群或发给老板） |
| 客户不用飞书 | 企微、钉钉、**艾玛（IMA）** 知识库，跟着客户适配 | WorkBuddy 和艾玛、微信生态连得比较丝滑 |
| 部门共用一台电脑 | 部门 Mac mini / Windows 上的 Obsidian + 企微 / 飞书 CLI | 也可以 |
| 小型项目 | WorkBuddy 项目资产 5GB | 再 Skill 关联飞书 / 企微库 |
| 国央企、上市公司非要本地 | 开源 **FastGPT** 魔改 | 多租户、权限、账号、网页导入、飞书 / 钉钉导入、Agent / 工作流 / MCP。现成工具更省事；Obsidian 本身免费，开会员多半为了备份 |

为什么这门课用飞书直播：讲师认为它是 AI 时代最好的办公工具之一。很多公司仍用企微，政务和大厂常用钉钉，交付只能跟着适配。

课上当场调起本地 FastGPT（密码都忘了，让 Codex 找回 `Root1234`）：开箱就有团队信息、第三方账号、模型与 API Key、语言时区；知识库支持飞书 / 钉钉导入、网页导入、爬虫；工作台能建搜索机器人、翻译、GitHub 总结，以及对话 Agent、工作流、MCP；管理员后台做账号和权限。GitHub 地址会发群。结论仍是：客户非要本地库可以魔改这一套，但比现成飞书 / Obsidian 麻烦得多。

```
原料原文 ──► AI 总结（二手，图文大白话）
                │
                ▼
           人消化（日记、决策、讨论）
                │
                ▼
           对外输出 ──► 提炼 Skill ──► Agent 日常调用
```

飞书跨文档：有阅读权限就能读；知识问答可以基于个人库、共享库统一提问。上下文爆掉不必过度担心——压缩技术已成熟，课上说 **1M 上下文可以塞约 80 万字**，到点会自动压缩、只留必要信息。飞书在云上，经 CLI 访问有延迟；机器人调用有月度上限（课上印象是一个月约 10 万次量级，超了可能另付）。个人 Obsidian 和团队飞书会有重合，课上估不超过 1/3。

## 十、课上问答里的硬问题

**智能表格只读头尾、中间丢掉；提成要跨「部门架构表 + 政策文件 + 业务数据」。**  
这不是「知识库坏了」，是模型和 Harness 的问题。换更严谨的模型（GPT、GLM，或更聪明的 Kimi K3；DeepSeek 也还行）。把表格链接、截图、字段含义写进 Skill，规定第一步取哪个字段、第二步取哪个。老板驾驶舱问法不可预判时，做**通用检索 Skill**：先让模型罗列表和字段，举几个例子，再让它写**程序脚本 / 函数 / 数据表**，不要用大语言模型硬算确定性结果。扬长避短，来回测稳定性。

**全体员工用：WorkBuddy 和飞书机器人怎么选？**  
来自建材行业客户的追问。不同情况用，不是二选一。WorkBuddy 一台电脑目前常只能接一个账号，企业版课上希望以后加多接口。巧妙写法：WorkBuddy 助理里配置飞书，变成群里 @ 的机器人。权限不同（财务 vs 水电工）：**两个机器人、两个群**，再加身份提示词；需要时用 Docker 或沙箱锁权限。防提示词注入只能做一定程度。

跨表格读取、飞书知识问答，前提都是「你对那篇文档至少有阅读权限」。没有权限，再强的 RAG 也翻不到书。部门共用一台电脑当知识库主机时，加企微或飞书 CLI 当接口即可，不必每人一份库。

## 十一、踩坑

- 为搭库而搭库，收藏夹越来越重，检索越来越吵
- 只保留结论，没有原文和来源，出了幻觉无法追溯
- 第一天不设计权限，后期补非常痛
- Excel 一转 MD 当数据库用，函数和关系全丢
- 中小公司一上来上本体论、GraphRAG，预算和周期都配不上收益
- 库上不长 Skill，知识不会变成日常封面、法务、选题复盘
- 不备份、不设删除钩子，赶上喜欢删文件的模型版本会一次清空
- 用自然语言让模型算提成、跨表统计，还怪「知识库不支持跨文档」

## 十二、这节课可以做的事

- [ ] 写四条本公司的优质标准：可追溯、可理解、可控制、可相信，并规定谁有管理 / 编辑 / 只读
- [ ] 按「原料 / AI 总结 / 人类消化 / 输出」建四个目录，先把原文完整存进原料区
- [ ] 盘一份清单：已有文档、缺口 SOP、必须访谈的老员工
- [ ] 用 MarkItDown 或 Skill 市场工具，把一批 PPT / Word / PDF 洗成 Markdown，人抽查验收
- [ ] 配一张飞书或多维表格，把「状态、负责人、日期、关联」从纯文本里拆出来
- [ ] 在一个真实场景上长出第一个 Skill（封面、法务、选题复盘均可）
- [ ] 给知识库加上定时导入、日志、备份和防删除 hook
- [ ] 能用一句话向客户解释：Markdown、关键词检索、RAG、图谱各解决什么，并说明你们现阶段用哪一层就够
