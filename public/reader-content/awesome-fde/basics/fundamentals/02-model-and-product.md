> **时长**：约 1 小时 59 分
> **核心问题**：给企业做 AI 服务，到底交付什么？

> **读本课**：整节讲 **AKA 框架与选型**。文中的 **K、A** 是「途经点 + 自动化路径」的预览；**第三节**专讲数据治理与知识库怎么搭，细节以第三节为准。

> **先抓主线**：客户不是来买模型名，而是想让某项工作变好。先说清任务，再判断需要什么 Agent、给它哪些可信上下文、哪些步骤值得自动化；工具选型放在这之后。课上的具体产品名单是当时的参考，项目中要重新核实版本、能力、价格和合规条件。

## 一、客户一定会问的三句话

1. 我们公司用 AI，能得到什么
2. 要用什么样的工具
3. 怎么用起来

市面上交付很乱：SaaS、垂直 Agent、大厂通用 Agent、一体机、咨询、培训、小工具定制都有。这节课不教「永远用某一个模型」，而教一套**几年甚至 10 年都未必过时的框架**。

两个月前 GLM 5.2 还是国内最强 Agent 模型，很快 Kimi K3 又上来。**模型吞噬一切**是现在的基调：去年用 n8n / 扣子搭的 Workflow，会被清洗进训练数据，下一代模型自己就会搭。25 年下半年，一小套工作流定制小一周还能收 8000、1 万；现在很难卖上价，工作流进化成了 Skill。工具会过时，框架要稳住。

## 二、AKA 框架

名称受 Codex 启发，课上写成 **Aka / AKA**：

**Agent + Knowledge Base / Database + Automation**

一个能干活的 AI，加上清晰上下文，再让它自动执行。

可以把 AKA 当成三个连续的问题：**谁来做（Agent）→ 按什么资料和规则做（Knowledge / Database）→ 哪些步骤可以稳定重复地自动做（Automation）**。遇到客户需求时，先逐项检查，而不是先挑一个最热的模型。

| 字母 | 含义 | 解决什么 |
| --- | --- | --- |
| **A · Agent** | 能干活的 AI | 不只是网页对话框 |
| **K · Knowledge / Database** | 清晰上下文 | 知道公司怎么干活、有哪些数据 |
| **A · Automation** | 自动化 | 让它自己去干，而不用人步步盯 |

> AKA 解决 80% 的问题。不管模型怎么变、应用怎么变，整体思路应该都是这样。

三个部件缺一不可：只有 Agent，它会在起点和终点之间「随便找一条路」；只有知识没有自动化，人还得频繁介入，客户会问「加了 AI 为什么没更省时间」。

```
Agent 能干活
    +  知识库 / 数据库（途经点）
    +  Skill + Cron + 目标 / 验收 = Loop
    =  企业里能跑起来的 AI
```

## 三、Chatbot 和 Agent 差在哪

客户常觉得：不过是把 DeepSeek / 豆包从网页搬到本地。必须讲清楚：

- **Chatbot**：网页对话，你复制粘贴，它回文字、图或视频
- **Agent**：能控制电脑。能写代码 ≈ 能操作文件系统、浏览器、办公软件

给传统行业、线下门店的统一回答：

> 但凡是白领工作，大概率都可以被 AI 替代。白领工作就是坐在写字楼办公室里操作手机和电脑。

演示最短路径：在本机输入命令打开 Claude Code / Codex / WorkBuddy，让它执行一条操作。对方立刻理解「这不是换皮聊天框」。

课上把口头说的「AI」校准成 **生成式 AI（GenAI）**：给一段文字，返回文字、图或视频。AI 作为学科有 70 多年（达特茅斯会议），高德导航也是 AI，但不是这类。生成式 AI 真正爆发是 **2022 年 11 月 30 日** 的网页版 GPT-3.5，到上课时大约三年。手机和电脑里的世界由代码构成，模型能写代码，就能通过代码控制电脑。

## 四、K：上下文是「途经点」

模型训练是 Transformer 猜下一个词的概率。「今天天气很」后面，「好」可能 55%、「晴朗」可能 20%，它选概率最高的。于是它喜欢在 A 点和 B 点之间自己找一条路——乍一看合理，其实是编的，这就是幻觉。

> 想让中间的路径符合你的要求，就在路上插途经点。途经点越多，它越按你的路线走。必须走深南大道，它就走深南大道。这个就叫上下文。

上下文两块：

| | 知识库 | 数据库 |
| --- | --- | --- |
| 形态 | 清洗过的文本，优先 **Markdown** | 关系、字段、状态、公式 |
| 为什么需要 | MD 是训练数据里最多的格式之一，「打娘胎里就亲和」 | Excel 转 MD 会丢函数；要保留关联 |
| 典型工具 | 个人 / 老板用 **Obsidian**；团队用飞书云文档、企微云文档；Agent 项目 5GB 资产；要求极高可魔改 **FastGPT** | 飞书多维表格（课上「目前最好用的数据库工具之一」）、企微智能表格、钉钉多维表格 |

知识从哪来（客户常常「没有知识库」，甚至没完成数字化）：

1. **纸质**：上海外企 Stellantis（汽车金融，劳斯莱斯 / 玛莎拉蒂租赁贷款）中国区法国老总，中文十级、看着像 80 后，开会仍用纸质笔记本。手写 OCR 很难，最稳是**访谈 → 录音 → 转文字 → 核对**
2. **基础数字化**（PPT / Word / Excel / PDF）：微软开源工具 **MarkItDown**（课上说 Markdown），Skill 市场搜「文档」也能装；让 AI 做清洗，不必人苦哈哈干
3. **脑子里的 SOP**：老员工、高管必须访谈蒸馏。Excel 转 MD 会丢函数，所以后面一定要知识库 + 数据库一起做

Obsidian 好卖：脑图像大脑神经元，再加老板看板 / 驾驶舱 / Dashboard，「满足老板的掌控欲」。缺点是难团队协作。个人隐私、要速度快的放本地 Obsidian（本地就是文件夹 + MD，不用每次用 user / bot 身份走飞书 CLI）；团队 SOP、客户文档走飞书或企微。飞书、企微、钉钉云文档本质都是 Notion 式块 + Markdown + Wiki 双向链接。

课上一个「千万级单子大佬」的销售问题：**你们公司用不用飞书？** 用飞书说明公司较先进，里面可能已有 AI 先锋和一堆 GPT / Claude 账号，能做的有限、不好要价；不用飞书，数字化往往没完成，反而大有可为。

多数中小公司，飞书云文档或个人 Obsidian 装几百篇日常文档就够。一个人岗位上能处理的文档课上估不超过 500 份、不超过 100 万字，可以塞进百万上下文窗口。**大部分场景没必要上 RAG 和本体论**——内部经营顶天 30%～50%，外部增长可以想 10 倍、100 倍，本体论成本高、收益窄。

课上提到一个可自学的技术名：**SAG Skill**（Skill + RAG），切片检索后再做 LLM Wiki 双向链接，把文档一和文档二放进同一张表，可能指向隐藏的文档三。基础课只点名，技术课再展开。

## 五、A：自动化怎么一步步走到 Loop

客户会问：人加 AI 还要每步检查、修改，工作量反而增加，为什么还要花钱？所以必须回答「它能不能自己干」。

自动化演进：

| 阶段 | 是什么 | 课上例子 |
| --- | --- | --- |
| **RPA** | 第一步点哪里、第二步点哪里 | 影刀那一类；Computer Use 里相当一部分就是 RPA；脚本有时也算 |
| **Workflow** | n8n / 扣子节点编排 | 当年一条工作流几千到上万 |
| **Skill** | 文件夹：核心是 `skill.md`（提示词）+ 参考文献 + 脚本 / Python | Anthropic 在 25 年下半年给出的规范；Workflow 本质是代码，现在交给 AI 写 |
| **Cron** | 定时触发 | 龙虾（OpenClaw）里广为人知的核心功能 |
| **Go** | 给一个目标，不达目的不罢休 | 「必须今天做出明年赚 100 万的计划」 |
| **Loop** | 循环自动干活 | **Skill + Cron + Go（目标 / 验收标准）= Loop** |

AI 工程四个阶段：

1. **Prompt engineering**：怎么写提示词
2. **Context engineering**：什么时候写什么样的提示词
3. **Harness engineering**：驾驭工程——把随机发挥的天才套上缰绳
4. **Loop engineering**：控制住之后让它自动干活

提示词工程师两年后基本没了，因为 AI 写提示词比很多人好。人要做的是：讲清第一步第二步，看效果，给反馈，迭代 Skill 版本。优质 Skill 仍要花心思。

能力太散时，可以封装成网页 / 小程序 / 内部应用：给 Agent 接口（模型 + Harness = Agent），加上知识库 / 数据库，把自动化收成按钮。年初有人喊 GUI 已死、CLI 永生；课上判断图形界面死不了。讲师抛弃 Claude Code 的原因之一，就是 Codex 图形界面用着舒服。

智能体对外可以说「智能体」，对内定义是：

> 知识库、数据库加 Skill，等于智能体。

## 六、2026 年国际和国内怎么选

| 市场 | 课上收敛 | 原因 |
| --- | --- | --- |
| **国际** | **Codex** 和 Claude Code，以及其他 | Claude Code 封号太严重，课上更推 Codex |
| **国内** | **WorkBuddy**，以及其他 | 同一水平线的国产竞品几乎没有 |

用国外 Agent 要先过三关：

1. **网络**：机场不稳定且封号严重；稍稳的是自建通道（课上原话：油管搜自建 VPS）、或向联通 / 移动 / 电信开跨境专线（要报备）
2. **账号**：封号后记忆丢失；个人账号之间很难协作；接飞书 / 微信还得自己手搓
3. **数据**：出境违规甚至违法；国外厂商「可以不讲武德」，拿数据训练，下一代模型内化你的流程——还是「模型吞噬一切」

WorkBuddy 的理由：适配飞书 / 企微 / 钉钉，不用从零手搓连接；数据不出境，过很多公司的合规红线；幻觉和 Harness 设计并不完美，但没办法，没有更好的国产选择。广东已发通知，WorkBuddy 进政务系统试点——国内没有第二家 Agent 公开做到这个级别。浙江卫健委培训里，华为电脑用的是**统信系统**，很多 Agent 装不上；培训结束第二周，腾讯官方公布鸿蒙 / 统信端的 App、小程序、电脑端适配。小团队自建三端，鸿蒙工程师贵，相关数据也没被训进模型，投入会被大厂抹平。

**要不要自建 Agent？** 线下有学员拿麦当劳一类连锁店客户，想本地或云上重做。课上建议：直接拿 Hermes 的 CLI / 终端版魔改（学员后来承认就是这么干的）。美团生活助手那种「给 AI 100 块钱去美团点外卖」是大厂生态测试，不是你该从零造的东西。除非国央企、大型集团对隐私要求极强，且预算到**千万级**，才考虑自建；所谓自建，多半是改 GitHub 开源项目改到客户用得舒服，不必从零造轮子。

WorkBuddy 里开 Auto，腾讯大概率会给你选混元 3（免费，好收集操作数据）。要精确选模型，不要依赖 Auto。

## 七、好 Agent 产品的三个板块

海外产品抄 Codex 时，三个板块几乎都会有。WorkBuddy 对得上：

### 1. 插件市场

WorkBuddy 里叫「专家团 / 技能」，背后是 Skillhub、MCP、CLI。好处：不必从零教 Agent 控制浏览器、控制电脑。课上操作：

- 搜 **PPT**，装一个 PPT Skill；再把部门模板丢给它，口头要求按模板生成并融合原 Skill 的排版审美，出样片后再改「太密、留白、字多图少」
- 搜 **CDP**，装浏览器自动控制，去操作微信小店后台、看数据、上架商品
- 连接器接飞书 / 钉钉 / 企微；本地助理可用手机 App 或小程序连本机

> Skillhub 里 99% 的 Skill 都是垃圾。搓不超过 10、20 分钟，拍个短视频说开源，第一步第二步其实是模型写的。

能用的是头部博主、真正有行业 know-how、还在反复迭代的。课上点名开源流派「动哥 / Don't be silent」（开源哥）那套 DBS Skill。浙江卫健委现场有人抱怨 WorkBuddy 做的 PPT 丑，当场在 Skill 市场搜 PPT 装上，比从零教强。

### 2. 项目 / 工作空间

Codex 的项目偏目录分类：一个项目对应本地一个文件夹，上下文在这个文件夹里共享。WorkBuddy 的项目不一样：

- 右上角邀请，链接进项目，人和 Agent 协作
- **资产**是项目内知识库共享，**5GB 云空间**（腾讯云）。电脑关了，项目里的任务还能在云上 24 小时跑
- **指令**就是以前的 Cosplay 提示词（你是某某专家，这个项目要做什么）
- 连接器不多：信通达、GitHub、腾讯文档、Notion 等少数几个
- Skill 在项目里**实时更新、实时共享**，不必再把 Skill 打成压缩包发群、拖进对话框重装
- 自动化、计划（待开始 / 进行中 / 暂停 / 已完成）、动态留言

5 月服务客户时，团队想过做「AI 中台」：公司完整上下文，人和 Agent 协作。两个月后 WorkBuddy 做出来了。课上的态度是：打不过就加入。

2 万篇纯 Markdown 总大小可以不超过 10MB，所以 5GB 装文档很宽裕；往里丢大量 PPT、图片会立刻膨胀。自媒体大量视频素材，5GB 不够；升级价课上看到约 **25 块钱 100GB**，中规中矩。企业版会有单独服务器方案。

### 3. 自动化（定时任务）

例如 Codex 定时收集微信消息、定时把飞书妙记存进本地知识库。云项目的价值：本地定时任务常因断电、断网、Agent 更新、系统卡死而停跑；云上 24 小时会跑。

WorkBuddy 必须打钱。腾讯云老总加过微信、送过企业版账号；二级代理卖企业版，返点课上说约 **30%～33%**。

## 八、2026 年 8 月的模型组合

课上强调：这是**现阶段**组合，群里会持续更新。各司其职，不要开 Auto 了事。

| 场景 | 课上点名 |
| --- | --- |
| 中文文本创作 | **DeepSeek**（又便宜又好用）。Claude 现在写中文不行；课上说最好的写作曾是 Claude 的 OPAAS 4.6，**4.6 之后全是「理工男的智障」** |
| 英文文章 | 仍是 Claude / Opus；4.6 好像只剩 API |
| 多模态、UI 审美 | 国内 **Kimi K3** |
| 编程 | GPT 的 **5.6 太阳模型**、智谱 **5.2**、K3 也可以；Claude 里最新是 OPA5、FAB 5 |
| 图片 | GPT 的 **Image 92**、字节的 **C-Grain 5.0 Pro** |
| 视频 | **C-Dance 2.0 / 2.5**，光影接近现实，贵、慢，但是 one shot 出片；早期用可灵、海螺 MiniMax、万象要疯狂抽卡 |

DeepSeek 在 WorkBuddy 里可本地配置 API（V4 Pro，由 preview 转正）。动态涨价，高峰可能双倍或四倍，但仍是国内最便宜：7×24 小时用不停，一周也用超不过 100 块。K3「贵的要死」。个人不必先买 WorkBuddy 各种会员套餐，先加模型 API。

Codex 真正好用的往往不是它的 Harness，而是 **GPT 模型强 + 自带生图（image）**。用 cc switch 换成 DeepSeek / Kimi：API 会丢功能，原账号聊天记录也会没。

讲师自己的用法：前期搜集、调研、脑暴用 AI；最后表达和思考自己来。对着 AI 稿子念，听众两句就能听出来，不会再看下去。

## 九、选型原则（怎么给客户拍板）

选型不是给产品排总榜，而是给具体客户的具体任务找合适组合。先问任务是否高频、资料是否可用、出错后果多大、要不要接入现有系统，再比较工具的能力、权限、成本和维护方式。下面的品牌、价格和部署判断是课程当时的经验快照，不应当作永久结论；实际交付前要重新验证。

1. 国央企、强监管、千万预算：才谈本地部署或自建；现有一体机显存几百 G（课上说 512G 可能几百万）顶多跑去年 600 多 B 的 DeepSeek，跑不了今年 2.8T 的 Kimi K3。本地部署 K3，硬件课上说 **1000 万起步**，还要 infra、硬件管理、微调、电力散热。1000 万买 K3 API「能用 1 万年」。除了极窄的私人隐私任务，**本地部署这条路必死**
2. 中国 80% 的企业：不必再造一个 Agent。安装 WorkBuddy，搭知识库，做 Skill，培训教会——授人以渔
3. 教框架，不绑死模型名。模型三个月一变，AKA 三个部件不变
4. 先演示「能控制电脑」，再讲知识库和自动化
5. **极简原则**：最简单、直接、有效。有标准 API 就把调用方式（地址、密钥、字段、格式）做成数据库 Skill；提示词会幻觉和漂移，Skill 里的**脚本和函数是确定性的**
6. 私域 / 微信自动发送：课上明确做过、也明确拒绝过。Computer Use 或脚本操控微信 / 企微容易秒退、封号；拆本地聊天记录有项目被腾讯起诉，涉及破坏信息系统安全，罚到几百万、几千万还进了人。企微 CLI 只能内部群机器人，做不了外部客户。等官方接口（课上提到企微将出的「大圆」客服助手，当时仍觉得有点垃圾）
7. 企业版 WorkBuddy：老板能看每人 Token 消耗，看不到本地聊天记录；员工离职账号可回收；协议上企业数据不被拿去训练。推理过程仍要把信息发到模型厂商 / 阿里云 / 火山引擎的机房，国内是签了协议的君子约定。模型优先选 **DeepSeek** 和 **智谱 GLM**（背后有国资委站台）
8. WorkBuddy 本机选本地文件夹，记录在本地；**项目是云空间**。手机助理可连，前提是电脑不断电断网。电脑和电脑之间的 WorkBuddy 不互通，不能用 Windows 控制另一台 Mac mini 上的实例。离职要走手续：退登、手机解绑、卸载

复购不要靠把客户养残：要么做成 SaaS 卖订阅，要么卖 Token。不把能力教会，客诉和运维电话会把你问死。

## 十、踩坑

- 给客户讲「换了个本地对话框」，讲不清控制电脑，单子停在认知层
- 为麦当劳式连锁店从零自建 Agent，忽略 Hermes 魔改和 WorkBuddy 生态
- Skill 市场装一堆 10 分钟垃圾包，当成品交付
- 用压缩包发群更新 Skill，团队版本永远对不齐
- 把自动化建在会断电的本地电脑上，定时任务说停就停
- 没有 API 还承诺打通十几年的 ERP / CRM
- 用自然语言硬控确定性计算（提成、对账），不写脚本 / 函数，Skill 必漂
- 接「抓微信消息并自动发送」，合同和刑法风险都在

## 十一、这节课可以做的事

- [ ] 用 AKA 三句话回答「你们到底交付什么」：能干活的 Agent + 可调用的上下文 + 能自己跑的自动化
- [ ] 准备 30 秒演示：打开 Codex 或 WorkBuddy，当场让它在本机执行一条命令
- [ ] 按客户红线做选择：国内团队默认 WorkBuddy；老板个人可用 Codex；千万级强监管才谈自建 / 本地模型
- [ ] 给自己搓一个个人工作台：一个项目、一份 MD 知识库、一张多维表格、一个定时任务
- [ ] 在 Skill 市场只装有行业 know-how、还在更新的 Skill，其余当参考不当时交付
- [ ] 有旧系统 API 时，把接口说明做成「数据库 Skill」，关键步骤用脚本而不是纯提示词
- [ ] 让 AI 根据这两节课的飞书妙记列一份补基础清单——课卖的是经验方法论，不是 B 站也有的名词
