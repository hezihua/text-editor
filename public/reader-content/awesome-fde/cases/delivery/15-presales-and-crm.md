> **课程来源**：FDE 实战训练营第一期 · 第 15 节
> **时长**：约 1 小时 32 分
> **核心问题**：单子怎么谈进来、方案怎么写成两份、客户和进度怎么管到项目能收尾？

本节目录：钱值不值 → 试讲与案例 → 用得上用得好 → 定制四问 → 售前 / 执行方案 → 四种生意 → 合同验收 → CRM。

前面三节偏执行：搭库、跑工作流、拆价格带。这节是脱敏案例最后一课，补**售前和客户管理**。周末密集补录播；学完后收集问题，下周集中直播答疑，一期课程基本结束。作业、线下参训、面谈、一年复训和回看等权益，以当时训练营公告为准。课程能带走的是思路和方法；没在现场带练、没亲手做，上完课不会自动会。

陪跑课上不作为主推：现阶段 FDE 做陪跑，但凡驻场、人天算不回来，大概率出问题。这节用**培训**和**定制**两条来谈。

## 一、谈判先回答一个问题：钱值不值

客户找你聊，老板真正关心的是：

> 我花的这笔钱到底值不值？

落到培训，会被拆成四问：

1. 员工**能不能听懂**
2. 听懂了**能不能用上**你讲的知识、能力和工具
3. 能不能**用好**；学完用不上、不会用怎么办
4. 培训完**还有什么服务**

现场会更脏。有的公司不用 WorkBuddy，用一个从没听说过的中转站 / Agent 平台；问「你们的 WorkBuddy 能不能接上我的中转站」，背后可能是 token 生意、AI 负责人是集团老大或高管的儿子。谈判策略是提供接口、把价值讲清楚，而不是在课上争论哪家平台正统。

推 20 万、30 万的**项目制培训**，对方一定会按小时算价值。三四十个小时，他会按一小时五千到一万来回算：凭什么值。纯讲课撑不住这个量级。

## 二、听得懂：试讲 + 案例，按「幼教」讲

先试讲，让拍板人感受你能不能把人讲懂。对象常常是部门负责人、集团高管甚至老大亲自拉会，年纪可能是 60 后、70 后，对 AI 没有那么深。课上给的比喻链：

- 现在大家说的 AI，多半是**生成式 AI**。跟客户讲 token 预测器，他听不懂；就说它在做文字接龙
- 网上的文字、书、语料丢进炼丹炉，炼出一个聪明的孙悟空，但仍是**失忆的天才**
- 课上现场算过：「今天天气很好」可能占 40%，「今天天气很不错」可能占 12%，它选概率最高的那个
- 他不记得昨天，必须把前因后果讲清——专业词叫上下文，对外就说前因后果
- 再换成：**很聪明、刚入职的实习生**。公司是什么、部门是什么、岗位要干什么，讲清了今天就能上手；讲不清就出错。什么时候讲清楚，什么时候能干明白

网页版 DeepSeek / 豆包，和 WorkBuddy、钉钉生态里的悟空 / 同类本地工具，区别怎么讲：网页版主要是聊天、出 PPT、出报告；**本地 Agent 能接管电脑干活**。以前人在手敲、人在点，现在让 AI 来操作。演示一次：让它操作飞书或多维表格、钉钉文档。2026 年这层能力，要用「哄小孩」的方式讲清楚。

试讲通过不等于成交。对方只是初步感到你会讲；还要案例证明「对技术不深的人听完能学会、能用到日常」。卫健委那单的分量在于：主任副主任回去能独立搓出交党费流程，科普岗能自己做图说科普，而不是听完只会点头。

能干活之后：知识库 / 数据库 = 把前因后果和怎么干讲给实习生；Skill / 工作流 = 让他自己干。试讲过一遍，只是初步感到你的能力，还要**案例**。课上举的是卫健委培训：来的是院长、副院长、主任、副主任，电脑本来不那么熟，学完能搓出自己能用的**交党费流程**，行政科普能做出「图说科普」公众号——分镜、生图用到日常业务。试讲 + 这种「回去能用」的案例，对方才肯信员工听得懂。

## 三、用得上、用得好：定制培训，而不是通稿

「能不能用上」先讲思路：开训前做问卷，和关键部门负责人做半小时线上或线下访谈，针对真实场景定制（招投标怎么写标书、招标标准、CAD 怎么画），课上一步步带操作，回去才能用。

项目制（大约 20～30 万）还要**争服务**：大班讲完，再筛部门里 **3～5 个**关键场景 / 项目做轻度陪跑。一个项目或岗位里需求不要超过约 3 个——标书撰写、审核、竞品比价，可以收在招投标这一个场景里。帮他们搭知识库和 Skill，确保场景用得出效果。纯培训、不带服务，就不要承诺这一段。

「能不能用好、能力长不长在他们身上」是下一问。越来越多客户不是零基础：WorkBuddy 装过，库和 Skill 也有，但是**零散**，个人提效串不成组织提效。少量库和 Skill 连不起来，懂一点的客户一定会问。答法是**分阶段**：

1. 大班：全员或核心骨干先学会、用上，具备基础能力
2. 下半场：重点项目轻度陪跑 / 轻度定制，你来帮梳库搓 Skill，他们直接用
3. 两个阶段里随时欢迎对方考察团队；第一阶段满意，再谈全公司库和 Skill、统一接口和中台——从零散的 10%、20% 甚至负增长，到打通后可能的十倍、二十倍质变

培训完还能谈的服务（看预算和团队能力）：智能体定制（本质仍是库和 Skill）；前瞻性方案（老师举例：网关层做计算机行为历史、员工使用痕迹监控——有足够预算才谈）；**顾问合作**——AI 变化快，老板和高管没时间盯行业，你们按月做老板或高管团队顾问。

这些是升单，也是回答「培训完还能不能解决别的问题」。顾问合作的卖点是确定性：市场一变，能很快给方向，而不是让忙于业务的老板自己追资讯。网关层监控、行为历史是「预算够再谈」的前瞻，不要在十万不到的培训单里主动摊开当标配。

## 四、定制谈判：定的是啥、多少钱、多久、效果怎么兜

客户会问四句：定制到底定啥；价格有没有参考；周期多久；怎么保证降本、增效或增收，效果不好怎么办。

对外可以说智能体、数字员工、AI 中台；对内要清楚：**智能体是错的概念**，AI 是上下文 + 工作流（token 预测器要灌上下文）。财务智能体只是为了让传统客户好懂，背后是大模型调知识库，用 Skill 做发票、算薪酬等。合同核对属于法务，不要塞错岗位。落地就是：知识库、数据治理、工作流，再加**把老系统接口串起来**（财务一套、工程一套、招投标一套）。

参考价课上给的底座：

> 一个具体的场景，对应一个智能体，对应一万块钱。

法务「合同草拟」是一个场景。客户会把「合同处理」扩成草拟、审核、审批、签署——一万元里**不要超过大约 3 个具体诉求**。例如草拟、审核、归档，算一个小场景、一个智能体、一万。超过对你不划算。

周期很难一口价：岗位和库的体量、工作流复杂度都不同。可参考：财务发票核对、法务合同审核，可能一两天；招投标写标书，可能一小周。按具体业务说「整体思路」，不要假装有精确甘特图。

效果和退款：

- **不要真往退款上承诺**。过往案例有降本增效，但从搭库、梳 Skill，到学会、用上、用出效果，需要周期。可能项目 3 个月搭完，再过 3 个月才见效；或要等全员能力和接口打通才质变，中间不好量化
- 先拉齐认知：学会用 AI 是难而正确
- 定制完有售后周期（例如一个月），可包一定运维——相应要收费。目标是**能力长在员工身上，资产沉淀在公司里**，带着员工补库、复训，而不是干完擦屁股走人
- 说服不了就转移话题，很难彻底保效果

上市公司 AI 负责人找外部，常常不是来替代自己：内部能做员工培训，说不动老板。外部负责：通俗讲会、给老板摆正「AI 不是神药」、顺手给可汇报的指标（WorkBuddy 安装率当普及率、某部门沉淀多少份资产、Skill 调用日志）。本质是给内部**偷时间发育**——第一个月干的事，可能三个月后才像那么回事。

## 五、售前方案和执行方案必须分开

售前方案在谈单阶段给，用来收集信息、对齐价值和边界，**不要写成可被白嫖的逐步操作手册**（第 1 节约定）。制作前先把信息收够：

1. 高管会谈
2. 高管一对一面谈
3. 业务骨干访谈
4. **Demo**（案例里最重要的是「做出了个什么」）
5. 流程步骤：第一步 / 第二步，第一个月 / 第二个月
6. **验收标准**：做到什么程度算好、算对方满意
7. 三档报价（基础 / 标准 / 满配）
8. **时间周期 = 交付边界**：哪些活干、哪些不干、付出多少时间；超过时间不在合同和承诺里

售前里可以写「客户能收获什么」、降本增效仅供参考；**最好不要把无法控制的效果数字写进合同**。方案可以虚一点，合同不要跟着虚。

执行方案进场后再给，核心是「什么人在什么时间干什么」：

| 块 | 写什么 |
| --- | --- |
| 负责人 + 执行团队 | 谁对外、谁干活 |
| 时间节点 | 什么时候、谁、什么事 |
| 任务拆解清单 | 搭哪些库、搓哪些 Skill——老板的「降本增效」太糊，必须拆到动作 |
| 资源支持清单 | **甲方**要提供什么 |
| 奖惩 / 分成 | 对内：做好怎样、做差怎样；总包分包各拿什么。智谱接千万级也不一定派人长期驻场，必要才去一次 |
| 结束验收 | 标准与时间 |

全国传统企业 AI 化，课上判断还很早期，没有到「五分之一已经完成」。跑得快的也是在按部门、按岗位搭库搓 Skill、做数据治理；一个部门省到钱，下一部门套不过去，卡在从个人提效到组织提效。

老板常见路径，课上说现在很多公司撞在同一类问题上：人在美国，看到某一波工具火了（课上点到龙虾 / OpenCloud 那一阵），觉得一定是未来，公司必须用起来 → 发现不够安全 → 又换成 WorkBuddy、Codex → 还是用不出效果 → 给人力 / IT / 数字化 / AI 负责人下「降本增效」。

降本落到动作上就是裁员，增效就是少花时间再加活。有的公司裁到大动脉、伤到骨干，才改口「不裁员、营收翻倍甚至十倍」——诉求仍然模糊。执行方案就是把这句糊话拆开：搭哪些库、搓哪些 Skill、甲方要给什么支持。

## 六、四种生意被 AI 串到同一张桌上

当天和战略咨询公司、上市公司聊，对方的判断：咨询顾问、培训、软件 SaaS、技术落地，从前是四种生意，现在 AI 把它们串起来了。咨询想做培训，培训想做 SaaS，SaaS 想做落地，落地又想回来做咨询。

| 生意 | 课上的比喻 | 卖的是什么 |
| --- | --- | --- |
| 咨询顾问 | 商业医生：问诊 + 开药方；分全科 / 专科 | 诊断和方案；传统咨询在下滑，所以找 FDE 或合作 |
| 培训 | **保健品**：吃不死、治不好，钱照赚，现金流好 | 认知和带练 |
| SaaS | 锤子打钉子，注定卖不太贵；订阅也不贵 | 工具 |
| 技术落地 | 人天；总包分包（金蝶用友、字节智谱千万单也不会自己驻场） | 脏活累活的工钱 |

AI 短剧、GEO 课上用来说明：利润高一定有人来分；门槛低（抽卡、剪辑 10 块一条；GEO 从 2 万 / 月打到 2K / 年）最后一定是头部占领、中腰部苟活、底部饿死。工具复制门槛被 vibe coding 拉低，就会价格战。甲方不管你付不付得起工资：SaaS 能解决就买 SaaS，要人定制就买定制，买完问效果。

FDE 工资（大厂六十万、一百万；海外按美元百万级挖人）课上看成虚高，职业有曲线，终会**价格回归价值**：开发出来的东西一定要能复用——库、Skill、数据资产，或一个完善工具加轻定制。最后拆成两笔：

- **工具的钱**：安装部署 + 订阅 + 运维。WorkBuddy 是市面上要做选型的工具之一。客户会问名牌还是杂牌、杂牌好不好用
- **人力的钱**：初级几千，好一点一两万，大厂工程师四五万，再往上十万也有。五万月薪的人接十万的单绝对亏——一个单至少三个人，再加谈单、差旅、请客，看似剩三万也值不回来。这种人要放到至少五十万、最好百万的单里。十万、二十万的单，配月薪一万的人或直接分包

FDE 往后是咨询 + 培训 + 工具 + 总包分包人天的结合。市面上在做工具选型，最终导向仍是给客户解决问题。

客户会问工具是名牌还是杂牌、杂牌好不好用。说服、销讲、产品效果都要为「解决问题」服务。

## 七、合同和验收：把三边拉到同一张纸

企业单最容易烂在「做完了但没说清什么叫完」。咨询公司、部门负责人、员工代表，预期经常不一致。最低限度：

| 条款 | 为什么要写 |
| --- | --- |
| 项目周期 | 陪跑按月，培训按天，不要混成一笔糊涂账 |
| 验收标准 | 多少人完成实操、哪条工作流稳定跑通；培训侧可用普及率、资产沉淀、调用率作汇报口径 |
| 验收时间 | 避免无限改需求 |
| 交付边界 | 超时、超范围不再默认包含 |
| 数据与保密 | 对应第 6 节：设备、权限、退出；驻场电脑清空签字 |
| 回款 | 预付、月结、尾款；小客户提高首付 |
| 效果数字 | 方案里可参考，合同谨慎写死 |

分成、协作，训练营强调白纸黑字，项目里同样适用。

## 八、客户档案和项目进度：给人看的表要瘦

给人看的表不要堆信息；细节进档案和「最新进展」。通用结构课上建议：

- **先分表**：按城市（杭州、上海、深圳）或按区；或按等级（S 级客户）
- **客户编号**：如 `S0001`，按你预估的客户量留位数
- 客户名称、客户预算（课上用「万」作单位，两位小数）
- 项目启动时间、验收时间；周期用公式算天数（多维表格可以让 AI 生成 `days` 一类公式）。课上随手填 8 月 1 日到 9 月，算出 60 天——评论就指出：**落地 60 天做不完，容易烂尾**；两个月培训还勉强，落地不要按这个周期骗人
- 项目回款（预算 100 万、回款 30 万也很常见）
- 负责人（人员字段）
- 项目进度：进度条、预计完成=验收日、实际完成或「今日」对比
- **客户档案**超链接

档案文档建议规范命名（最好做成 Skill），课上演示的层级是：

1. 客户基础信息（可再拆一份独立文档）
2. 客户沟通记录：按年 / 月，挂飞书妙记、智能纪要、原文（如 8 月 10 日、8 月 15 日）
3. 客户方案记录：售前方案 V1、后续版本
4. 聊天记录汇总：微信 / 钉钉 / 飞书 / 企微
5. **最新进展**：根据档案和最新妙记，每天（或定时 Skill）总结进度——给人看的主表只留这一格入口

命名带上客户编号，例如 `S0001-客户8月沟通记录`，避免档案一多就对不上。

AI 要的是完整上下文；人要的是能扫一眼的预算、周期、回款、负责人和进度。定时任务 + Skill 更新「最新进展」，客户管控就清楚很多。第 13 节的表格，首先是给自己用的。

## 九、一期训练营的闭环

```
市场与能力（01）
  → 选型与 AKA（02–03）
  → 组织与商业（04–05）
  → 合规（06）
  → 名词与装库（07–09）
  → 自动化与部署（10–11）
  → 价格带案例（12–14）
  → 售前与客户管理（15）
```

回去能做的最小动作：选一个真实客户或自己的公司，按 AKA 写一页诊断，再决定它是千元、万元还是十万的故事；同时从第一次接触就建档案——来源、行业、预算体感、已经用过的工具、反对者是谁。

## 十、这节课里点过的坑

- 用模型名词跟 60 后、70 后拍板人讲 token，而不用失忆天才 / 实习生
- 纯讲课要 20 万、30 万，对方按小时一除就不值；项目制却不带 3～5 个场景的轻度陪跑
- 售前方案写成可逐步复制的操作手册，执行细节被白嫖
- 把「降本 30%、增收十倍」写进合同，而不是写进方案里的「仅供参考」
- 一个「合同处理」按一个场景收一万，里面塞了草拟、审核、审批、签署
- 给人看的 CRM 主表堆满妙记和聊天，领导扫一眼找不到预算、回款、负责人
- 落地项目按 60 天验收，课上随手算的公式都会被一眼看穿
- 五万月薪的人去交十万的单；工具选型纠结名牌杂牌，却说不清解决什么问题
