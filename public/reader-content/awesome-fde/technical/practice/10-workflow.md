> **课程来源**：FDE 实战训练营第一期 · 第 10 节
> **时长**：约 1 小时 15 分
> **核心问题**：AKA 里第二个 A 怎么落地？什么时候点鼠标，什么时候拖方块，什么时候只下命令？

技术课实操。数据库不再展开：中小公司用飞书多维表格或企微智能表格就够；制造业 / 电商 / 大型集团自建 ERP，才谈到工程级库，以后单独录加餐。

三个 AKA 零件：

- **Agent**：能干活
- **知识库 / 数据库**：知道该怎么干
- **Automation**：让它自己去干

没有第 08、09 节的知识库，自动化只会稳定地做错事。先 K 后 A，顺序不要反。

这节也是两段，不要混：

| 段 | 干什么 |
| --- | --- |
| **前半** | 认三代：RPA（抖音导出）→ Workflow（飞书 8:30 催更）→ Skill |
| **后半** | 当场做一个 Loop：WorkBuddy + **飞书 CLI** + **定时群消息日报** |

```
飞书 CLI 授权（用户身份读群）
    ↓
指定课程群，拉今天的消息，生成摘要
    ↓
用机器人身份试发一份
    ↓
补 Goal（范围、脱敏、失败怎么办）
    ↓
定时（每天 12 点）→ Loop
```

RPA / n8n 是选型菜单。课上真正带练完的，是后半这条链。

## 一、三代自动化：什么时候用哪一层

### 1. RPA：步骤固定，模仿点击

第一步点什么，第二步点什么。适合界面稳定、没有复杂判断。

课上完整例子是抖音运营每天导出作品数据：

1. 打开抖音创作者中心
2. 点「数据中心」
3. 找到「作品数据」
4. 点「导出数据」下载 Excel
5. （可再精细）昨天 / 近 7 天 / 近 30 天，或从 7 月 1 日到今天；下一步还可以把表写进多维表格

老师在 WorkBuddy 里做了一个按钮，点一下运行，就按人类路径把数据拉下来。能做成这样，是因为第 09 节装了**浏览器自动化、CDP**，又加了拓展 **Browser Skill**。

RPA 本质是一串脚本，去读网页元素（HTML 组件）。网页最好做，因为元素和协议都暴露着。客户端软件没摊开元素，就只能 Computer Use：截屏 → 识图 → 把鼠标挪到坐标再点，所以慢。细节放文末答疑，不挡主路径。

### 2. Workflow：加上判断和定时

和 RPA 都是「第几步做什么」，中间多了条件、分支、定时。背后是编码，封装成组件后才能拖。

典型产品：**n8n、扣子、飞书多维表格自动化**。

课上从选题管理系统右上角空白新建，最小例子：

1. **触发**：定时，当天 8:30，不重复
2. **动作**：给自己发一条飞书消息——标题带生气表情、红色背景，正文催更，底部按钮跳回选题排期表
3. **再加条件**（演示到分支，没全部做完）：本周内再往内容群发；过了这周还不更新，再发企微公司群

8:30 到点，消息真的来了，按钮能跳回表格。哪怕「定时发一条消息」，手写也是一串代码；点加号加步骤，才变得简单。

问题：对人的要求仍然不低。老师经历过大公司、小公司、创业公司和头部公司，**真会搭的人不多**。所以不要逼客户学 n8n。

### 3. Skill：人只下命令

Workflow 太重时，把 RPA、工作流、脚本都交给 AI 写，人用自然语言触发。Skill 规范从 Claude Code 一带出来，现在是企业交付的主流封装。

## 二、Skill 怎么写才不像「你是专家」

核心文件是 `SKILL.md`，**本质上是一套提示词**。更早的形态是 cosplay：「你是某某专家」。只给提示词，模型容易自由发挥。课上的「洗车难题」：家门口 50 米有洗车店，走路去还是开车去？很多模型说走路——车还在家里，怎么走过去洗？要从随机发挥变成确定，就要写脚本。

课上拆过年初的 `agent-team-manager`。一份不容易跑偏的说明书，至少能回答：

1. 谁是负责人、谁是执行者；负责人只规划、拆任务、汇报，**不能下场干活**（下场写代码 / 写报告，上下文会爆炸）
2. 开工前要不要对同一张任务列表，完工要不要更新进度
3. 子 Agent 跑完能不能自行解散（年初跑完就关，上下文容易丢；要等你确认再关）
4. 遇障重复尝试几次后必须停，向谁求助（领导用更聪明的大模型，执行用更便宜的小模型）
5. 大任务和小任务分别几个人；三种委派：代码开发、内容创作、商业分析
6. 哪些事写成脚本，不让它自由发挥
7. 参考手册和模板放在 Skill 目录，还是只写「去 Obsidian 某路径查找」

更完整的目录常见是：

| 部分 | 装什么 |
| --- | --- |
| `SKILL.md` | 角色、步骤、边界、输出格式——核心出装 |
| `scripts/` | 真要跑的代码，钉死不让它乱发挥 |
| `references/` | 参考手册；也可以写明去知识库哪找，避免把 Skill 撑太胖 |
| 模板 / 素材 | 例如封面生成 Skill 里的脸模、3D、旧照片索引 |

当模型足够强，`SKILL.md` 和脚本都可以让它写；参考手册你写完丢给它保存。杭州导游库若已按第 09 节装进飞书，下一步不是手搓 n8n，而是把「按预算出一日游」写成 Skill，把库路径写进 references。

写 Skill 不是炫技，是把「熟练员工脑子里的 1、2、3」写成模型不容易跑偏的操作手册。

## 三、主流程：WorkBuddy + 飞书 CLI + 日报 Loop

有了 Skill，再加定时，就接近自动执行。课上把这条走完整：定时收集课程群消息，做成一个 Loop。

### 1. 两种定时不要混

| 类型 | 课上说法 | 风险 |
| --- | --- | --- |
| Agent 级 | WorkBuddy「自动化」、Codex 小钟表「已安排」 | 龙虾时期很容易失灵：派了活，过几天发现任务一直没跑 |
| 系统级 | 电脑上的定时脚本，到点给 Codex / Claude Code / WorkBuddy 发一段文本 | 只负责监控和启动，更稳 |

老师自己的 Agent 级例子：每隔 3～4 小时汇总微信消息；每天凌晨 3 点用飞书 CLI 把录音豆 / 妙记归档进 Obsidian，之后才能问「上周跟刘总聊了什么」。

只说「定时去抓」会抓成一团乱：所有窗口都抓、昨天抓过的今天再抓。必须补上 **Goal**：范围、验收标准、截止时间、去重、失败怎么办、什么时候停。

> 目标不是说你让他做什么事情，不是说让他赚到 100 万。

阿拉丁神灯：许愿明天 100 万，还要写清不能违法、不能从银行凭空消失、来源干净、永久在自己账户。约束写全，模型才干得好。

**Skill + Goal + Cron = Loop**

WorkBuddy 里点「测试运行」，本质是往一个**新窗口发一段提示词**：任务目标是 Goal，执行步骤是 Skill，安全隐私限制也是 Goal 的一部分。不在这段提示词里，就还没写成 Loop，只是设了个闹钟。

循环不是一劳永逸，要持续检查、迭代。Cloud Code 的创造者上半年说，自己每天的工作就是写 Loop。

### 2. 当场带练：课程群消息日报

把整条复现成作业：

1. **飞书 CLI 授权。** 连接器里没有飞书，就自然语言：「帮我安装飞书 CLI，发起授权，尽可能授予所有权限；我要创建一个飞书机器人，以我的**用户身份**读取聊天记录。」
2. **为什么强调用户身份：** 飞书有 bot 和 user。机器人不在群里就读不到；人在群里，才能用用户 ID 读。老师保险起见，飞书相关事都用用户身份。
3. 指定群名（可加引号），测试拉取「今天 0 点以来」的消息。
4. 整理生成摘要，先用**机器人身份**发你一份试跑。
5. 再设定时：例如每天中午 12 点，用 bot 身份发总结。
6. **补 Goal：** 仅限这个群，不回复其他群；涉及 App ID、App Secret、API Key、身份证、银行卡一律剔除隐藏；失败要通知你。
7. 打包提交：**完整 Skill 文件夹 + 运行结果**。不要打包密钥和其他群内容。

课上演示拉到当天 18 条消息，能和群里逐一对上；机器人「五竹」发出日报（条数、活跃成员、关键动态）。WorkBuddy 自动化列表里出现「FDE 训练营群消息日报，每天 12 点」。连撤回的消息都能读到——权限有多大，边界必须写死。

读群用 **user 身份**，发日报用 **bot 身份**。两个身份不要反着用。授权链接会申请大量权限（课上演示过三百多项）。本周内前提交，按评分 Skill 评一次。

> 你不要把它搞复杂了。……真正难的在 Skill 里面。

## 四、怎么跟客户选型

| 情况 | 用什么 |
| --- | --- |
| 界面点击、导出报表（抖音创作者中心这类） | RPA / 浏览器 Skill / CDP |
| 有审批、有分支、要通知多人 | 飞书 / n8n / 扣子 Workflow |
| 要复用、要培训、要交给客户自己跑 | Skill |
| 客户完全不会搭工作流 | 不要逼他们学 n8n，封装成 Skill |
| 要每天自己跑、还要验收标准和失败预案 | Skill + Goal + 定时 → Loop |

网页、能在线打开的后台，最适合 RPA。企业通用知识库只能放文化、规章制度、公用信息；客户 CRM 等敏感信息要分开部署——这是第 06 节的续篇。

同一件「把后台数据拿下来」可以落在不同层（下面是归纳，课上并没有把抖音导出真做成 n8n）：

| 成熟度 | 抖音这个例子可以怎么做 | 人还要干什么 |
| --- | --- | --- |
| RPA | 按钮：打开后台 → 数据中心 → 作品数据 → 导出 | 点一次运行，检查下载 |
| Workflow | 每天定时导出后写入飞书表，异常发群 | 看分支有没有配错 |
| Skill | `SKILL.md` 写清账号、日期范围、存哪张表、失败找谁 | 验收格式；登录态仍由人看管 |
| Loop | Skill +「只导未导过的日期、失败飞书通知我」+ 定时 | 每周看一眼日报，改 Goal |

能接的是创作者中心导出、飞书群日报、选题表催更这类**界面稳定、权限清晰、失败可通知**的闭环。客户若问微信自动回复，用第 06 节一起答：技术上能描述给 WorkBuddy，政策上和封号赔付接不住，所以不接。

## 五、课后问答（不挡主路径）

**RPA 认的是网页元素，不是你眼睛看到的布局。** 页面不是全屏也能操作，甚至可以在后台打开网页。找不到稳定元素、只能扫坐标时，就要接受 Computer Use 又慢又脆：截图 → 识图 → 移鼠标 → 再截。能在浏览器里完成的，优先网页元素。

课上用「检查 → Network → media」说明网页把音频源文件暴露出来了，RPA 读的就是这类组件。客户端（飞书桌面端逐步点击、微信）没把元素摊开，就只能上 Computer Use。

**个人微信自动回复：理论上能，实际上不行。** 微信会秒退、出风险提示。即便模拟打字、随机间隔，也隔绝不了风控。号封了要赔钱，所以不给客户做。技术上自然语言描述给 WorkBuddy / Codex 就能搓，风险不是技术能解决的。

## 常见坑

- 没有知识库先上自动化，错得又稳又快
- 用 RPA / Computer Use 去控个人微信，给客户做自动回复
- 觉得「会拖 n8n」是门槛，逼客户学工作流，而不封装 Skill
- `SKILL.md` 只写「你是专家」，没有步骤、边界、脚本
- 负责人 Agent 下场干活，上下文爆炸
- 只设 Agent 级定时，不管失灵、不管失败通知
- 定时抓取不写范围、去重、停止条件
- 作业打包时把密钥和其他群内容打进去
- 飞书只用 bot 身份，机器人不在群里却怪它读不到
- 读群和发报把 user / bot 身份用反

## 这节课可以做的事

- [ ] 把自己的一项重复劳动写成 RPA 四步（对照抖音：打开哪个后台 → 点哪 → 导出什么）
- [ ] 在飞书多维表格里搭一个最小工作流：定时 + 发一条消息，跑通一次
- [ ] 打开一个现成 Skill，确认 `SKILL.md` 里能找到角色、步骤、边界、输出；有的话再看 `scripts/` 和 `references/`
- [ ] 完成主流程：飞书 CLI（用户身份读群）→ 摘要 → 机器人试发 → 补 Goal → 定时 12 点
- [ ] 点一次「测试运行」，检查新窗口那段提示词里是否同时有 Skill、Goal、安全限制
- [ ] 打包 Skill 文件夹 + 运行结果（脱敏、无密钥）
- [ ] 对客户讲选型：点击用 RPA，分支用 Workflow，复用和培训用 Skill，每天自己跑用 Loop
