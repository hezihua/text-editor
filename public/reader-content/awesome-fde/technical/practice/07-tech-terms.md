## 一、人为什么要发明 AI

上世纪已有冯·诺依曼架构的计算机：二战破译密码时，人发现思考和计算的规则可以写成公式、电路，让机器执行。体力劳动被精确计算之后，铁匠的「手感、火候」变成工业流水线。于是有人继续问：脑子里的工作经验，是不是也能被计算，变成**智力流水线**？

1950 年代达特茅斯会议前后，第一批人开始做这件事。当时脑科学不够，只能像中医那样从**表象**判断：望闻问切，数据堆得够多，就能从症状推病症。图灵测试也是同一逻辑——你同时和一个人、一台机器对话，分不出来，机器就算通过。这两年大模型其实早已通过，这个测试过时了。

三条技术路线可以记成递进：

| 阶段 | 做法 | 限制 |
| --- | --- | --- |
| 符号主义 | 把规则写成程序，机器按 1、2、3 执行 | 只能执行你写清的规则，涌现不了智能 |
| 机器学习 | 给数据和算法，让机器自己找规律 | 规律可能乱七八糟，你也不知道对不对 |
| 神经网络 | 用公式模拟神经元连接，再训练 | 能「找猫」，但内部仍是黑盒 |

「找猫」是课上反复用的例子：一堆图里找出小猫，再精确一点找出黄色小猫。流程是：模型做题 → 人类标注师改卷 → 用 **Loss（损失函数）** 算错了多少 → **反向传播**调参数，让误差变小 → 再做题。一开始 10 次对 3 次，调着调着 10 次对 7 次。

> 你不知道到底为什么调了这个参数，它的错误答案就少了，它只是知道这么做它就错误减少了。

这就是「思考过程是黑盒」的根。人只观察到 **Scaling Law（规模定律）**：数据、参数、算力堆到一定程度，它会像人一样**突然开窍**，出现质变。GPT-3 到 175B 参数时开始能聊天、写方案；再往后，模型里甚至出现课上说的 **J space**：自言自语、自己骂自己（DeepSeek 用户见过那种）。把这段思考删掉，它会一下子变傻，从推理模型变成快速模型——像往脑子上打一拳。

顺带两个交付判断：

- 垂类模型越训可能越窄、越钻牛角尖。大模型要「学富五车」才聪明。电商模型如果不同时懂自媒体，就涌现不出「怎么给电商做自媒体」。很多时候砸几千万训垂类，还不如直接用 Kimi、DeepSeek
- Kimi K3 到 2.8T 参数，本地部署成本课上说在 **1000 万往上**，只有少数极大集团扛得住

想看训练入门，老师点名卡帕西（Karpathy）在 YouTube 上的系列，很多 AI 工程师、训练师从那里启蒙。

## 二、一个大模型是怎么炼出来的

把上面收成一条能画给老板看的流水线：

```
互联网文本 / 书籍 / 代码 / 论文
        ↓ 清洗（去重、过滤、规范化，常整理成 Markdown）
      Token（文字变成机器能算的数字）
        ↓
 Transformer（2017，《Attention Is All You Need》）
        ↓ 预训练：预测下一个 Token
    Base Model（聪明但没情商的「小白」）
        ↓ 后训练 Post-training（言传身教）
      上架的 LLM（Kimi / GLM / DeepSeek …）
```

Anthropic 被骂过：在工厂里把纸质书切开、一页页扫描再喂给模型。原始数据很乱，必须先洗干净。洗完仍是中文、英文——机器不懂字，要 **tokenize**：把字符变成 Token。

老师的比喻很直：

> 假设 FDE 它的代号叫 9527……那在机器那边收到的不是 FDE，是 9527 这个数字。比如说今天我们去公园散步，它就变成什么 3.14159265。

**128K 上下文**里的 K，指的就是 Token。上下文窗口 = AI 的脑容量。以前不够大，只能把记忆压成短提示词；现在窗口越来越大，能装的上下文也越多。

2017 年 Google 发表 *Attention Is All You Need*，把 Transformer 的自注意力机制写清楚。GPT 里的 **T，就是 Transformer**。有了它，预训练只做一件事：给定上文，猜下一个 Token 的最高概率。

> 今天天气很，下一个字是什么？一般来说今天天气很好……在中文语境下，「今天天气很好」是一个 55% 以上的概率会出现的事情。

预训练出来的是 **Base Model**。它还不是市面上的 Kimi、DeepSeek。比喻是《黑客帝国》里刚出场的机器人：有点聪明，但没有知识经验，也没有情商。**Post-training（后训练）** 相当于往脑子里植入芯片——不要讲违法、不安全的话，人类喜欢怎样回答，好的回答长什么样。做法包括数据标注、监督微调、强化学习（RL）。

> 你前面就是生出来一个孩子，后面是干啥呢？给他言传身教，就像训狗一样。

训完才能上市：智谱发 GLM、Kimi 发 K3，这时才叫可公开使用的 **LLM（大语言模型）**。

## 三、提示词为什么叫提示词

模型一直在做条件概率。你写提示词，就是在改它下一步的概率分布：「提示一下，我想要你给我什么样的回答。」

一套能用的结构，课上至少四块（老师口头数到「第五个板块叫输出」，和「示例 / few-shot」是同一块）：

1. **任务**：到底要它做什么
2. **背景 / Context**：前因后果，需要它知道什么
3. **限制**：要做什么、不能做什么
4. **输出 / 示例**：参考案例。这里有个词叫 **few-shot（少样本）**

少样本不要学成四不像：让 AI 扒三个风格完全不同的博主的爆款，再让它学，会学歪。样本要集中、相似。好样本比形容词更管用。

大语言模型：你给一段文字，它回一段文字。同一套机制扩到图、音、视频，就是 **AIGC（人工智能生成内容）**。

## 四、主线：Token ← Prompt ← 优质上下文

只靠你问我答，它会失忆。最早的**上下文工程**非常朴素：把聊天记录打包，再当提示词送进模型。后面所有形态都从这一条长出来。

> 后面所有的这些都是基于这个 token 和 prompt 衍生出来的不同的形态。

| 形态 | 人话 | 课上细节 |
| --- | --- | --- |
| Context | 把记录打包再送进去 | 它才知道前因后果 |
| RAG | 开卷考试，翻自己的书再答 | 聊天记录 + 问题一起发给模型，回本地知识库找资料 |
| Memory | 反复要用的上下文存下来 | GPT 最早做：聊天总结成 300～500 字，上限大约 200 条，放进自定义，当 **system prompt** 每次偷偷带上 |
| 联网搜索 | 补训练截止日期之后的事实 | DeepSeek V4 预览版课上印象是训练截止 **2025 年 5 月**；之后的事不开联网它不知道 |
| Thinking | 一步一步推理，不要跳步 | 1+1=2，2+3=5，5+5=10，再推回 1+9=10。跳步像灵感迸发，容易错 |
| Deep Research | 联网 + 深度思考绑在一起 | 能搜、能想、能聊，变成 Chatbot |

所以主线可以倒着念：

**Token ← Prompt ← 优质上下文**

模型有训练截止日期。截止日期之后的事实，不开联网搜索它就不知道。联网搜索本质仍是：补一块更准的上下文。

早期模型都是「快速模型」。DeepSeek 刚出来时，模仿贴吧老哥恶评又快又爽，问深一点就不会。于是有了深度思考。再往后，ChatGPT、豆包、Gemini、DeepSeek、Claude 都能聊、能搜、能推理。只会聊天的应用早期大量做成角色扮演、情感陪聊——情绪价值，当玩具，成不了主流商业。下一步必须让它**干活**。

## 五、随机性和幻觉从哪来

Token 预测从诞生起就是猜。猜就会有随机性，猜就会猜错。同一套提示词换窗口、换日期，答案不一样，就是漂移，也是第 1 节说的「不确定」。

工程上能做的是收紧提示词和知识库、用检索代替让模型「回忆」、加校验和人工终审，而不是幻想零幻觉。深度思考是在降低跳步，不是消灭概率。

## 六、2025 年怎么让它干活

课上两条大路，再加上工作流和本机 Agent 的演进：

### 1. Coding 路线

Function Calling / Tool Calling。代表是 Cursor 这类 IDE：AI 辅助写代码。现场按一下唤出 Claude Code，老板立刻懂：

> 它既然能写代码，它就能够控制你的电脑去干活。

现在主流是从 Chatbot 走到 Coding Agent；办公 Agent 也建立在编程能力上。

### 2. 工作流路线

- **LangChain**：手写代码，把模型、工具、记忆串起来，是一套开发架构
- **Workflow**：方块、菱形、线条，背后仍是代码，但重复逻辑封装成组件，可拖拽、可可视化。给客户看一串代码他不会买单，看第一步第二步才卖得动

编程能力 + 各行各业沉淀下来的流程数据，再放进云端虚拟机 / 沙箱，就出现了 Manus：让你看见它打开文件夹、新建文件。现在 WorkBuddy、Codex 展示干活过程，最早是 Manus 在做。

### 3. 从命令行到本机

最早直接在你电脑里干活的是 **Claude Code 的 CLI**。Skill 规范也是 **2025 年下半年跟着 Claude Code** 出来的。2026 年 1 月底、2 月初 OpenClaw（龙虾）在国外火，3 月传到境内，纯 Vibe Coding 出来，安全漏洞多，不能当企业默认方案。后面 Hermes、Codex 接力；图形界面比命令行好用。Claude Code 因封号太狠被很多人放弃，国际上 Codex 成主流，国内又有网络、账号、数据安全问题。WorkBuddy 界面很像 Codex，是国内能在电脑里干活的一条路。

能写代码 ≠ 能上线。第 1 节说的「花瓶和屎山」，根子多半是前期 Plan / 架构没想清楚。Karpathy 先提 Vibe Coding，后来又提 **Agentic Engineering**：开发、测试、运维一整套，不是纯自然语言就能做出生产级应用。

## 七、权限：关在小房间里，还是套上缰绳

龙虾那一波之后，大家特别怕它把东西删掉。两种做法：

| 做法 | 含义 |
| --- | --- |
| Workspace | 只在本地一个文件夹里活动 |
| Sandbox / Docker | 默认权限关在沙箱里；Docker 一定程度上隔离环境，「两房一厅里关一个小房间」 |
| Hook | 例如拦截乱删文件（老师说 GPT 喜欢删东西），先拦住再确认 |

关太死，每一步都要你审批，自动化就烦。于是又要适度放开：Claude Code 的危险模式（bypass permissions）、**Agent Browser / CDP**（控制 Chrome）、**Computer Use**（截图识图，模仿人看屏幕、点鼠标、敲键盘）。不是所有软件都开放接口——微信写代码去控会秒退——能控浏览器，就能覆盖大量网页后台的活。

再往上是 **Harness 工程**。Harness 是马术场里的马鞍和缰绳：模型像赤兔马，很聪明但不懂事。

> Model 加 Harness 等于 Agent。

Harness 三大块：

1. **接口**：API（用得最多的是模型 API Key）、CLI（例如把飞书用法变成模型能读的代码 / 上下文）、MCP（模型上下文协议；老师觉得有点过时，可被 Skill 替代）、Plugin（WorkBuddy、Codex 里很多插件本质就是 Skill）
2. **上下文**：知识库、数据库、Memory
3. **工作编排**：Skill、Workflow、Hook、Subagent

Subagent 出现，是因为号称百万上下文的模型，窗口过了 30 万、40 万就会变蠢。多开一个小窗口，像多招一个人。现在上下文压缩已经比较成熟：超限前先在后台总结再送回去。老师自己偏懒人操作，让它自动压；有同学建议用 Hook 设计压缩规则，老师认为更好。

记忆本质上都是**外挂大脑**：设置里的个性化、system prompt、外挂记忆系统、知识库 / 数据库、Skill 里的操作手册，最后都是变成提示词再送到服务器。本地部署大模型成本已经吓人，老师判断本地大模型这条路很难；本地小模型 + 蒸馏 + 成熟 Harness，才比较现实。Skill 和记忆的边界不必抠死：Skill 优化推理流程，同时也是上下文的一部分。

自动化那条线先记公式，下一节展开：

**Skill + Goal + Cron = Loop**

## 八、为什么又回到 AKA，以及怎么讲给老板

串完名词会发现：让 Agent 能干活，是大厂在做的事。FDE 能做的是中间的上下文——知识库、数据库，Skill 也算上下文，但更偏工作流自动化。同一套 Skill + 知识库框架可以给不同客户做一遍，就可以想标品化：部署安装 + 知识库定制 + Skill 微调，减轻每次从零定制的压力。

再往后：接到飞书 / 微信 / 企微 / 钉钉，前提是有一台 Mac mini 或 24 小时开着的笔记本，人在手机里下命令，它在办公室干活。复杂系统要好用，往往更复杂；接一个聊天窗口会变简单，但很多能力只能在本地实现。

给老板的三句话可以收成：

1. 模型是「猜下一个字」的机器，不是真理机器
2. 你给的上下文越干净，它猜得越准
3. Agent 比网页聊天强在能动手，不强在更不会说错

## 九、用一条故事线串给客户听

给非技术老板讲时，不要从 Transformer 论文讲起。按老师收束时的顺序，就是人类一直在让机器学习人的思考习惯：先写成规则，再让它自己找规律，再堆数据和算力等它开窍；开窍之后用提示词跟它说话，用上下文和记忆让它记得住，用 RAG 和联网让它翻得开书，用 Coding 和 Computer Use 让它动手，用 Harness（马鞍缰绳）让它别把房间拆了，用 Skill 和 Loop 让它自己连续干，最后接到飞书或微信，人在手机里下命令。

对应到 AKA：

| 字母 | 客户能听懂的话 | 卡在这节的哪个名词 |
| --- | --- | --- |
| A · Agent | 它能打开电脑干活，不只是网页里聊天 | Coding Agent、Computer Use、Harness、Skill |
| K · 知识库 | 它猜下一个字之前，先翻你们公司的书 | Token、Prompt、Context、RAG、Memory |
| A · Automation | 到点它自己去干，失败了会喊人 | Skill + Goal + Cron = Loop |

现场若被问「那它为什么还会说错」，回到概率：它从训练第一天就是在猜下一个 Token，猜就会猜错。你能做的是把草稿纸洗成 Markdown、把反复要用的话变成记忆、把公司资料变成可检索的上下文，而不是幻想换一个更贵的模型就变成真理机器。

WorkBuddy 相关、课上问到的落地细节也可以记在坐标系边上：它对中转不太友好、偏 chat 接口；企业版多出来的是管理后台（角色、Token、操作日志、离职收账号），聊天记录仍在本地。CC Switch 一类工具用来统一管各家 API Key、切 Kimi / 智谱 / DeepSeek 等，老师并不建议「都用得上 Codex 了还去切便宜模型」。这些都不改变主线：产品长什么样，最终仍是 Token 和 Prompt。

## 常见坑

- 把 Base Model 当成已经能用的 Chatbot，跳过后训练
- 提示词只有「帮我写一下」，没有任务、背景、限制、示例
- 用三个完全不同风格的爆款当 few-shot，学成四不像
- 不开联网却问截止日期之后的事实
- 把 OpenClaw 当企业默认方案
- 权限全开或全关，没有 Workspace / 沙箱 / Hook 的中间态
- 以为 Vibe Coding 能从 60 分自然长到生产级 90 分
- 中转站接口和 WorkBuddy 不对付：课上说它对中转不太友好，只支持 chat 接口；企业版和个人版界面几乎一样，多的是管理后台（账号、Token 消耗、操作日志；**聊天记录在本地，后台看不到**）
