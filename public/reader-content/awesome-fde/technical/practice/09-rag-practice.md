| 半场 | 谁讲 | 你要带走什么 |
| --- | --- | --- |

| **下半场** | 十三老师 | RAG 原理加餐：小抄、八步、FastGPT。库很小时先不必上 |

> 知识库它只是一个工具，工具它是为了解决问题而存在的。

上一节有人跟着操作会跳步。这节上半场把隐藏步骤走一遍；主路径不是 Obsidian，也不是先上向量库。

```
需求梳理（人）
    ↓
WorkBuddy 计划模式（把需求说清楚）
    ↓
飞书 CLI 授权（一次授满）
    ↓
WorkBuddy 在飞书创建知识库 / 写文档 / 建目录
    ↓
10 道真问题检测
```

浏览器 CDP、小红书 MCP 是**采集旁路**。FastGPT / 向量库是库变大以后的事，放到下半场。

## 一、先梳理需求，再发给 WorkBuddy

和第 08 节同一套问诊：先问「这个库解决什么问题」，再问「要覆盖哪些信息」。不要把作业说明书整份丢给模型——中间的拆解，才是 FDE 要练的。

作业要做出**最小可用**的杭州导游库：能按时间、预算、兴趣推荐景点，能说清位置和场景，能给出火车站 / 机场 / 地铁到主要景点的公共交通，还要有小红书真实种草。

假设对面是杭州景点相关公司，五类需求（后两类常被漏）：

| 需求 | 库里要装什么 |
| --- | --- |
| 景点推荐 | 知名景点盘点、特色、适合场景、内部政策、价格 |
| 路线规划 | 距火车站 / 机场 / 地铁方便的点；一日游 / 两日游常规路线 |
| 预算盘点 | 价格对应到项目、服务内容、时间周期 |
| 适用场景 | 约会、团建、出片机位 |
| 真实种草 | 小红书笔记 + 评论区；先判断是不是商单；每点大约 3～5 篇 |

把这五类**写成你自己的话**，发给 WorkBuddy，并补两句标准：

1. 朋友来杭州，能快速推荐合适、舒服、有真实评价的景点和路线，方便带人接客
2. 资料从哪收、小红书怎么采，要它调研相对安全的接口（API / MCP），不要自己瞎爬

> 你直接丢给他的话，你中间的思考过程可能就没有了。

原版作业写得很细（例如不少于 12 个景点）。老师后来删模糊，是怕大家失去拆问题的训练。验收标准仍建议自己拆到可检查，见文末作业。

## 二、主流程：WorkBuddy + 飞书 CLI + 飞书知识库

这是上半场要反复走通的一条链。人动嘴，Agent 在飞书里干活。

### 1. WorkBuddy：开计划模式，先规划再动手

课上模型用当时最聪明的 **K3**。先开**计划模式**，让它列出：还缺哪些库、去哪收、用什么载体。它会抛选项，课上选法：

| 决策点 | 课上选法 |
| --- | --- |
| 载体 | **飞书**（多维表格 / 知识库文档都可以；也可 Obsidian / 本地 Markdown） |
| 范围 | 杭州市区 |
| 种草采集 | MCP 半自动（登录后以你的身份抓；控频率，机械高速采集容易封号） |
| 交付 | 先做最小可用样板，再扩 |

老师会把自己 Obsidian 里的工具清单丢给它，让它在本地合集里找小红书 MCP，而不是两眼一抹黑上网搜。执行中要盯着：登录失败、窗口不对，就停下来改方向。当时 WorkBuddy / Claude Code 不能像 Codex 那样中途按 Enter 改道，只能先停再发。

复杂任务开多个窗口并行（老师说自己可能开 10 个）。人的工作变成：指导、审查、看有没有干偏。

语音输入比手打快。细节课上提过豆包输入法更保上下文，不是这条主流程的关键。

### 2. 飞书 CLI：一次授权，打通读写

WorkBuddy 对飞书、钉钉、企微有连接器。课上说法：自然语言即可——「帮我下载安装飞书 CLI，发起授权」。

**一次性全量授权。** 舍不得授满，后面每个新任务都会喊没权限。

接上之后，WorkBuddy 才能：

- 在飞书里**创建知识库、建文件夹、写云文档**
- 读飞书妙记链接当课程助教，不必：点进妙记 → 导出文字 → 再上传
- 把 README、MOC、子目录文档直接写进飞书

没有 CLI 的土办法，是你自己导出再喂给模型，课上明确说「很麻烦」。接上 CLI，才是「动嘴、它往飞书里装」。

课上演示：把第 08 节妙记链接丢给已授权的 WorkBuddy，它就能梳理主线；再加一句「村口 60 岁大爷也能听懂」，它会把 Markdown / 切片 / 向量化 / RAG 讲成人话。这是同一条链路的副作用：飞书里的课，变成可问的助教。

### 3. 飞书知识库：一个需求一个目录

分类最高频、最普适的切法：**一个需求一个子目录**，不要按「我以为的旅游分类」切。

```
飞书知识库（杭州导游）
├── README（这个库解决什么问题）
├── MOC（哪些文档在哪）
├── 景点推荐/
├── 路线规划/
├── 预算盘点/
├── 适用场景/
├── 真实种草/
└── 检索测试题/     ← 单独文件夹
```

来源标注也要留下，接第 03 节「可追溯」。冲突默认**以最新为准**（去年票价 vs 今年票价）。

README、MOC、子目录都可以让 WorkBuddy 写，人把要求说清即可。飞书云文档本质是文本，可下载为 Markdown。课上示范指令大意：

> 按这五个需求创建五个子目录，分别保存；然后在飞书上创建一个知识库。剩下的他自己会去干。

采集来源通常是：官网 / 文旅公告、公开的地铁公交高铁机场、小红书帖子。收完统一成 Markdown，再按景点或需求拆目录。

等它跑完，飞书里既可能是长文，也可能是景点总表、预算速查表、场景匹配等**多维表格**——这也是一种搭库方式。

### 4. 用 10 道真问题验收

库在飞书里装好，回到 WorkBuddy（已接飞书 CLI）直接提问，不要只看「文件夹在不在」。10 道题至少覆盖推荐、交通、预算、场景、种草。答不出就回去补文档，不要先包装网页。

飞书自带知识问答有时搜不到库里明明有的内容（第 08 节测过）。接了飞书 CLI 的 WorkBuddy 反而能找到——所以验收以这条链路为准，不要被飞书自带问答误判成「库是空的」。

进阶才是包 Skill、做成网页应用（群里已有同学做）。主路径走完再包。

## 三、旁路：浏览器 CDP 和小红书采集

主流程不依赖浏览器。采集网页、扫码登录、抓已打开的页面时，再装：

1. **CDP / 浏览器自动化 Skill**：让 WorkBuddy 控 Chrome。装好后不必再堆浏览器插件。规则可以写成：不要新开窗口，直接操控已登录的旧窗口，避免反复扫码
2. **小红书 MCP**：半自动、控频率；需要可以准备一个小号

旁路的产出，仍然写回**飞书知识库**，不要另起一套收藏夹。

## 四、下半场：RAG 是什么、什么时候才要上

上半场教的是「简单知识库」：资料进飞书，Agent 用关键词 / CLI 去读。当库大到模型窗口塞不下、关键词对不上意思时，才要向量检索，也就是 RAG。

### 1. 人话：递一张小抄，不是让模型变聪明

十三老师用热水器说明书引入；曲老师用村委会账本。可以叠，不要混角色。

| 术语 | 人话 |
| --- | --- |
| Markdown | AI 最顺眼的统一草稿纸。PPT / PDF / 录音都先抄成它 |
| 切片 | 说明书太厚，撕成一张张小纸片；真正管用的往往只有半页 |
| 向量化 | 每张纸片按一个「指纹」（一串数字）。电脑不懂意思，但懂号码近不近 |
| 检索 | 按指纹找最像的几张。「老王爱吃什么」对不上关键词「偏爱甜瓜」，意思检索能中 |
| RAG | 开卷考试：先找到纸条，再对着纸条回答。三个字母 = 检索、增强、生成，人话是**查、加、答** |
| 向量数据库 | 放纸条的柜子 |

> RAG 它并不是让 AI 变聪明，而是我们要去给它递一张小抄。

没有检索的对话是闭卷。朋友学问再大，没见过你家热水器，修起来也对不上。把整本说明书塞给他，书越长越难翻到那半页。RAG = 只递正确的那半页。

### 2. 和上半场那条链的关系

| | 上半场（飞书简单库） | 下半场（RAG） |
| --- | --- | --- |
| 资料放哪 | 飞书知识库 / 云文档 / 多维表格 | 切完的小抄进向量库 |
| 怎么找 | 关键词 + WorkBuddy 读飞书 CLI | 问题也编号，找指纹近的几张 |
| 适合 | 文档少、总字数远小于窗口（课上口径：例如 10 篇、十万级） | 企业到很大、或窗口只有 64K / 128K |
| 和 Obsidian | 更像把原文直接交给 AI | 中间多了拆纸、编号、进柜、近邻 |

库很小时，全文丢进百万窗口的模型和 RAG 差别不大。课上说可以把飞书 / Obsidian 理解成「简化版检索」，但逻辑和完整 RAG 不一样。**不要 10 篇文档就上企业级 RAG。**

给客户讲，按热水器故事一口气说完，不要先丢 FastGPT 截图。村委会账本接在「先统一成 Markdown」那一步。

被问「那我 Obsidian / 飞书不就行了」：文档少就行；到 TB 级或窗口很小，才需要中间那些步。知识图谱能写纸条之间的关系，效果更好，但字节 2024 年知道、至今没做，因为太重——FDE 默认先 RAG，不先卖图谱。

### 3. 十三老师的八步（加餐）

前四步建柜子，后四步回答：

1. 有一份原始资料
2. 拆成小纸片（每张带着原文、号码、来源，才能回原文核对）
3. 给每张纸编号（向量化）
4. 收进柜子（向量数据库）
5. 用户的问题同样编号
6. 找出意思最近的几张小抄
7. 问题和纸片一起交给 AI
8. AI 按资料组织回答

现场 demo 用《笑傲江湖》做成 3D 点云。问「令狐冲的独孤九剑是跟谁学的」，会亮出相关片段，再和问题一起发给模型。小抄可调：1～3 张或 10～20 张，多给几张通常更稳。

平台实操走 **FastGPT**（开源，群里发了链接）：登录 → 知识库 Tab → 上传 → 设切片规则 → 预览分块（课上精简文档切成 72 个小抄，更长的切过 926 段）→ 索引向量化 → 用「搜索测试」看命中。这套界面主要做完**前四步**；把切片再发给大模型，很多产品要外接模型 API。群里另有一份最小 Python 实现，对应这八步。

三个容易错的环节：分块（切太长太短会丢信息）、编码（号码不准找到错纸条）、生成（资料递到面前仍不按资料答）。让它更准：多留上下文、多找几张小抄、回答标来源。进阶名词只要求知道：按标题建索引、切片 overlap、多路召回和重排。

记住三句：

1. RAG = 先查再答
2. 号码挨得近，意思就近
3. 小纸片准不准，决定最后答得准不准

GraphRAG / 本体论：普通 RAG 不太描写纸条之间的关系；图谱会量化关系，成本更高。和第 08 节「图谱太重」是同一条线。KAG 等变体只点名，不展开。

加餐作业：按群里步骤体验一遍 FastGPT，中间过程录屏提交。向量库往往是本地部署、或库已经庞大时再上；知道流程、能给客户讲清楚即可。不要求这节就给客户上线一套自研 RAG。

## 五、作业怎么验收

自己练习时，仍建议把最小可用拆到可检查（即使原版 README 被删模糊）：

- 景点库：不少于 12 个点；每个点至少有名称、类型、推荐季节、政策、价格、适合场景
- 交通：火车站、机场、地铁到主要景点，以及一日游 / 两日游各一条常规线
- 预算：价格对应到项目和服务内容
- 种草：每点 3～5 篇，附评论对比和「是否商单」
- 来源：链接可追溯
- 测试：10 道题；答不出就回去补，不要先包装网页
- **载体**：飞书知识库由 WorkBuddy 经飞书 CLI 写入，而不是你手工复制粘贴

采集冲突写死「以最新为准」，并在 README / MOC 里声明。

## 常见坑

- 作业说明书整份丢给模型，自己不拆需求
- 没接飞书 CLI，还在点妙记导出文字
- 飞书权限舍不得一次授满，后面每个任务卡授权
- 目录按「我以为的旅游分类」切，不按客户问题切
- 把 CDP / 小红书 MCP 当成主流程，飞书库是空的
- 用飞书自带问答测失败，就以为库没装上（换接了 CLI 的 WorkBuddy 再测）
- 小红书机械高速采集，不控频率
- 库只有 10 篇就上企业级 RAG
- 只建 FastGPT 知识库，以为八步都做完了（可能只做了前四步）
- 切片过碎导致信息丢失，却不回头调分块

## 这节课可以做的事

- [ ] 把杭州导游五类需求写成一段提示词，**不要**整份说明书粘贴
- [ ] WorkBuddy 开计划模式，选定载体为飞书，先列「还缺哪些库、去哪收」
- [ ] 安装并**一次授满**飞书 CLI，用妙记链接验证它能读飞书
- [ ] 让它在飞书创建知识库：五类子目录 + README + MOC + 测试题文件夹
- [ ] 用接了 CLI 的 WorkBuddy 跑 10 道回归题
- [ ] 需要采网页时再装 CDP；需要种草时再上小红书 MCP，产出写回飞书
- [ ] 用「热水器说明书 / 小抄」给一个非技术同事讲：飞书简单库 vs RAG 各何时用
- [ ] 有余力：按群里文档在 FastGPT 走一遍切片和搜索测试，加餐录屏提交
