飞书文档左侧目录很短，这就是前半场的骨架：

1. **AKA 框架**（Agent / 法务知识库 / 自动草拟、自动审核）
2. **1、一份好的 Spec、Plan 长啥样？**（清晰的任务指令 → 目标 → 功能 → 体验）

老师原话大意：正常给客户交的，就是他电脑上的一套 AKA。法务顾问演示走的就是这条稿。

```
填 AKA（WorkBuddy + 法务库 + 两个自动化）
    ↓
写 Spec / Plan：目标、功能、体验、边界
    ↓
先规划两条 Skill，再封 localhost 网页
    ↓
口语 + 截图改 UX，全程留 log；体验够了再重开一局
```

WorkBuddy 工作空间、Codex 跟进、飞书多维表格是**补课旁路**。

## 一、课堂拆解稿（对照飞书文档填）

把这份稿当成交付单。先填 AKA，再写 Spec；空着的格子就是还没想清楚、不能丢给模型开写的。

### AKA 框架

飞书文档原文：

| 层 | 文档怎么写 | 课上怎么落 |
| --- | --- | --- |
| **Agent** | Codex、WorkBuddy | 统一用 **WorkBuddy**，避免不是人人都能上 Codex |
| **K** | 知识库，法务知识库 | 合同模板库 + 判决案例库；通用法条只作演示 |
| **A** | 自动化，自动草拟合同，自动审核合同 | 两个 Skill，再封装成本地网页 |

知识库搭建不在这节重讲。通用库（工信部、最高法、宪法、通用法、裁判文书网、地方法院、合同模板、律所观点）共享没问题，但没有太大价值：

> 你要解决垂直问题，你比如就是你搞 AI 行业的，你就把 AI 相关的一些法律法规，然后合同案例库，然后判决库，然后相关的一些法律观点……收集进去。

老师已经让 Codex 抓过一堆公开资料。对 WorkBuddy 的指令是：基于模板库、案例库，再调研网上法务顾问 JD，调研完再做两个 Skill，**先规划两条工作流怎么实现**，并开计划模式。

交付拆全了还有第四步 **教学**（入门、过程中、收尾各训一次，回扣第 01 节）。飞书这份拆解稿只写到 AKA 三件套，教学不在这张稿上。

### 1、一份好的 Spec、Plan 长啥样？

飞书文档先写：**清晰的任务指令**。再往下拆四格。课上说 plan、spec、PRD 叫法不同，本质是同一份「这事怎么做」。封装网页之前先写这一份，不要直接写代码。

| 格 | 文档怎么问 | 法务顾问这次怎么填 |
| --- | --- | --- |
| **任务指令** | 清晰的任务指令 | 基于本地模板库 / 案例库，调研好的法务顾问怎么草拟、怎么审核，做出两个 Skill，再封成网页 |
| **目标** | 做成啥样？ | 打开网页就像有一个法务顾问 |
| **功能** | 应该有什么能力？ | 只要两件事：**合同草拟**、**合同审核** |
| **体验** | 第一步做什么？ | 草拟：问合同类型、甲乙方、板块和诉求，支持点选、粘贴或语音。审核：基于本地库指出风险 |
| **边界** | （文档体验后面还要补；课上当场加的） | 严格遵循本地法务知识库；本地和公开权威来源都查不到，就说不知道或不确定，**不能编造幻觉** |

还要让模型反问：哪些地方不清晰、有歧义、后面会出 bug。反问时把它当成**村口 60 岁大爷**，技术名词必须翻译成人话。规划看过没问题，再往下执行。

模型补了一个老师没先想到的点：审核要选立场（甲方 / 乙方），关注点不一样——这就是 Spec 里「体验」没写清、被反问出来的格子。

## 二、自动化容易被听错

第二个 A 不是「AI 全自动，人可以消失」。最近跟大量客户聊下来，这个歧义还在：

> 自动化不是纯粹让 AI 自动化……你让它自动化的事情，往往是重复的、标准清晰的、目标明确的，评价标准也比较清晰。

更稳的分工：

| 交给 AI | 留在人 |
| --- | --- |
| 重复、步骤清楚、好坏标准明确 | 判断、审美、对客承诺 |
| 定时触发的固定动作 | 手动触发、中途改方向 |
| 模板式起草、按规则初审 | 幻觉边界、最终签字 |

课上例子是课程 PPT Skill。老师每一次仍要告诉它：第一页讲什么、第二页讲什么、封面有什么内容。发给它之后，它再调用 PPT Skill，按已经规定好的画风、排版、字体、元素去出一份。这是**人手触发**的自动化，不是定时全自动，但仍然算自动化。

结构也写死在 Skill 里：封面页 → 个人介绍页 → 正文按逻辑顺序 → 最后 Q&A。人负责「这一讲的内容」，Skill 负责「这一家的样子」。

> 这样就有分工了，有些是纯粹 AI 自动化，有些是人类和 AI 协作的自动化。

这叫 **human in the loop**：人是自动化的一环，不是自动化的对立面。跟客户先对齐这句话，能少掉一半预期事故。飞书稿里的「自动草拟 / 自动审核」，指的也是这种：人填信息、选立场，AI 按库出初稿，签字仍在人。

## 三、Vibe Coding：言出法随，但不随

老师把 vibe coding 译成中国老话：**言出法随**。杭州导游 Skill 做成网页 / 小程序 / App，好像许个愿就能实现，所以它火。真正的问题在后半句：

> 言出，看起来法随，但实际上不随。

一句话做一个网页很爽，但你为什么要做网页？解决什么问题？当玩具，创造一时爽，维护掉层皮。用 AI 编程之前，先想清楚要解决的问题——所以飞书稿把 Spec / Plan 放在动手前面。搭知识库也是同一顺序：先问客户要解决什么，再动工具。

全网没有通用标准。老师自己的高光聚焦 Skill，是为了讲课标出讲到哪一页，开源到 GitHub 也能当商品；但「靠 AI 编程做一个工具卖钱」很难。做 FDE 时，不少行业大佬和投资人一开始完全看不起这个生意，觉得太非标，应该做标准化产品。后来精准企业客户找上门，给了内测账号，测下来大部分产品要么垃圾，要么说不清和 WorkBuddy 有什么区别。

标品更难卖高价。个人 SaaS 月费 99、199 已经算贵；企业版按年卖 2 万、4 万、8 万差不多。培训项目可以做到 10 万往上。标准化产品要卖高，必须成为头部、有流量体量，否则开发成本都覆盖不回来。市面上不缺「还能看」的产品，缺的是好产品加好营销。

前端早年 AI 做的网页丑丑的。老师早期抓 Twitter 消息的「AI 信号场」，后来被卡兹克的 AI hot 头部斩杀。现在 Kimi K3、更强的模型和 design 相关 Skill，UI 已经能做好看。**审美是人类需求的最大公约数**：很多人觉得一张图好看，它就算有审美。

UX 是另一回事：点进去一眼看到哪些功能、第一步点什么、跳到哪。这个 AI 替代非常有限——所以 Spec 里要单独写「体验」。后端是你看不见、却支撑网站跑起来的逻辑，也是最容易出 bug 的地方。GPT 类模型干活慢，但后端更扎实；再加 Super Powers 一类开发架构或开发 Skill，后端会越做越好。前后端都能在一定程度上让 AI 做，就没必要再开一门从 Python 打印 hello world 讲起的课。

跟工程师朋友聊下来的结论：AI 执行越来越好，人要回到独属于人的职责——**plan / 架构设计**，定义好看不好看、好用不好用。规划清楚，再用更好的模型去执行，bug 会少很多。前期把一堆功能堆在一起、逻辑没梳清，后期一定是恶心、解不掉的 bug。AI 编程让每个人都成了老板，就要先当好老板。

传统完整编程：发现问题 → 验证需求 → 产品定义 → UX/UI → 后端架构 → 拆计划执行 → 测试 → 发布 → 迭代 → 退役。很多人现在的 vibe coding 变成：突发奇想 → 丢给 AI → 得到 **60 分 demo** → 越改越出新 bug → 掀桌子。从 60 分到 90 分很难。中间态叫 vibe building：先有流程、页面、功能块、库和测试，再上线。再往上是 **agentic engineering**：把过去研发团队的流程请回来，每一块让 AI 辅助，最要紧的是 spec、架构、plan。

两个壁垒留下来：

- **工程能力**：想法变成生产级应用，前后端规划清楚，少出 bug
- **产品能力**：真懂用户需求，做出能解决问题的东西

前端想好看：用更有审美的模型（Kimi K3、Claude 一类；GPT 更理工男），加 design Skill，或买好看页面的源码作参考。也可以先让 GPT Image 出一张页面图，再 1:1 复刻成 HTML，大概七八十，细节仍要补。后端少 bug 的最强解法是更强模型再加 Skill；有的 Super Powers 并不适配新模型，反而限制发挥。

## 四、按稿执行：Skill → localhost → 改 UX

Spec 填完，规划通过后，先出一份 localhost 能打开的网页。课上点出来的体验大致是：

1. 打开页就两个大按钮：草拟、审核
2. 草拟：选合同类型（演示用了「AI 定制开发合同」）→ 填甲乙方 → 选立场 → 金额、付款、期限、交付物、成果归属、是否接触客户、争议地、违约金算法 → 生成初稿 → 复制 / 下载 Word
3. 审核：选立场 → 出审核报告 → 结论后**人工复核** → 再下载 Word

秒出初稿，是因为背后有模板，不是魔法。测的时候问题马上出来：Word 表格被压扁；审核只让粘贴全文，真实场景该上传文件。这正好说明——

> AI 它不能够做用户体验设计，它只知道说，我这个地方能够让你正常运行。

改法是口语加截图：「表格被压扁了，要保证完整查看」；「加上传，不要 Ctrl+C / Ctrl+V」。改的过程全部留 **log**。体验到还不错之后，老师习惯「重开一局」：告诉模型前面踩了无数坑、改了几十上百遍，现在按已消化的审美和功能**完全重构**。像打游戏输了重开，水平已经上来了。

把 AKA 封装成应用，好的 vibe coding 是让客户点两下、填信息就能用；界面不需要多好看。天天审合同，赏心悦目是加分，真正值钱的是识别出公司对法务只要两件事：草拟、审核。更深的股权建议、公司规划，留给真正的法务顾问去收咨询费。

完整改法可以当成交付习惯：

1. 先规划、调研，出飞书稿上那份 Spec / Plan
2. 人检查规划是不是自己想要的样子
3. 照着做 demo，从头到尾体验
4. 口语 + 截图提修改；**中间所有改动写 log**
5. 体验到还不错，再「重开一局」完全重构——你已经知道要什么功能、什么审美

> 真正难的是你怎么一点一点的把这个细节……完善出来。

## 五、作业和上线

简单作业：复刻这个合同草拟 / 审核网页。复杂作业（群里另发）：做一个能给股权建议、公司规划的初级法务顾问——需求很糊，考的是你能不能从头拆能力，而不只是套模板。降幻觉、去 AI 味放到下周，这节不作为重点。

Localhost 要变成线上站点：人只负责买腾讯云 / 阿里云服务器、买域名、登录；其余「帮我部署到网上」交给 AI。小程序更复杂，要专用工具或小程序 Skill，可能走 ICP 备案；有支付还要备案。微信支付可以找封装好的 Skill；老师需要支付时放到小程序，因为当年微信对 AI 小程序有扶持，官方支付组件现成。购买、下单、登录 AI 做不了。

## 六、补课：WorkBuddy 交付现场会卡住的用法

三个大板块（插件市场、项目、自动化）前面讲过。这节补的是学员卡住的用法。老师没预料到飞书和 WorkBuddy 的日常操作还有这么多人不会，所以后半场专门补。

**工作空间**就是本地文件夹。新建「AAA 建材老王」或「培训演示」文件夹再打开，旁边就是独立项目。文件都落在这个目录下，点加号可以开只属于该文件夹的对话。

**连接器**能挂百度网盘、腾讯地图、法律检索、飞书等。连上飞书后，既能读飞书里的知识，也能模拟你的用户身份去办事。日常办公 / 代码开发只是底下应用和对话风格的差别；创意开发已拆成单独产品。

技能市场按关键词搜，例如搜「PPT」。**专家**就是一套搭好的知识库加 Skill。复杂任务先开**计划模式**：先规划再干活。群里有人 200 刀、20 倍 Pro 的 Codex 两天把周额度烧完，多半是上下文管理差——子 Agent 换省一点的模型，加上先规划，会好很多。

本地助理连微信小程序，可以在手机上遥控。设置里「添加模型」：把自己的智谱 coding plan、Kimi、DeepSeek 的 API key 贴进去。配好自定义模型后，不必再买 WorkBuddy 个人会员。DeepSeek 开放平台充 500，不特别频繁大约能用三个月（价格会变）。选模型时要拉到**自定义模型**那一段，前面是套餐内模型。

上下文窗口大约一百多 K，快满了就主动压缩。**远程锁屏**打开后，电脑不关机、不退出 WorkBuddy，家里或办公室那台只要不断电断网就能连上——有好处也有坏处，按场景开。

飞书知识库有时在桌面端、有时在网页：头像 → 设置 → 效率 →「链接打开方式」选优先在飞书导航栏打开，并指定默认浏览器。

## 七、企业版多出来的，是管理，不是另一套界面

企业版登录后，界面功能和个几乎没区别。多的是企业管理后台：组织概览、成员与额度、代码行数监控、加量包。个人用，老师建议自己买大模型 API，通常更便宜；企业客户才买席位。

后台可以自建企业智能体（例如 CRM 销售 Agent），加技能、关联知识库、开记忆，全员可见并发布后，客户端「助理」里会出现企业智能体。项目里的专家团、共用空间当时还不完善，偏待开发。模型管理可以规定全公司用 DeepSeek、开发部才能用 K3。还有 playbook、公司 Skill 上传、会话 / 自动化 / 操作日志。对话日志打开后可追踪使用与合规。网络设置能做 IP 白名单，例如只许公司内网访问。自定义模型也可以加自己的 key。

席位大约两个人三百多、一个人一百多（当时价格），贵在管理后台：成员用量、组织用量、谁是超管。内置模型消耗的是会员积分；积分不够再充，不是「开了会员还按 token 另计」那种算法。外部模型偶尔连不上，重新添加一次通常就好。企业智能体、企业专家、企业 Skill 这些团队共用能力，老师觉得确实有用，后面值得单独写测评。

「更建议开 WorkBuddy 会员还是自己付费大模型？」个人用：自己买 API；企业用：席位加管理后台。

## 八、补课：Codex

Codex 和 WorkBuddy 大差不差，但不太匹配国内生态。它有拉取请求、代码库安全扫描、偏国外的插件（Google、Slack）。定时任务类似。**站点**能把 vibe coding 的结果快速部署成网站——课上例子是「离家近、比较好吃的餐厅」，可浏览、加餐厅、看人均、包厢、低消。Codex 偏个人；WorkBuddy 很多交互是在抄它。

几个常用设置：

- **完全访问 / 从不请求审批**：省得一直点批准，追求自动化的人会打开（按自己风险偏好）
- **工作目录**：和新任务，跟 WorkBuddy 一样
- **发送跟进**：执行中途可以改方向。老师举例：正在做微信汇总，发一句「今天先暂停」，它会停。WorkBuddy 任务没跑完，消息发不出去
- **自定义指令**：没有现成的 `agent.md` 时，用 `codex.md` 加 hook，每次强制读取——重复规定放进这个文件
- **Chronicle 研究预览**：关掉。否则会在后台截图，把电脑上的数据喂给 OpenAI
- 浏览器 / computer use：老师全都打开，方便操控；内置浏览器可开可关

**Agent.md**（Claude Code 里常叫 `CLAUDE.md`，OpenAI 生态里也有类似文件）是**家规**：公司文化、制度、常踩的坑。每次执行必须按统一制度来，属于强制外挂记忆。

## 九、补课：飞书

这节只补交付用得到的，不是另开一节飞书课。

- **机器人**：用飞书 CLI 发起授权、创建应用后出现机器人，可拉进群、@ 问答。老师把 Codex 接到飞书机器人上，手机端 ChatGPT 远程连接加载太慢，日常在飞书里聊就是在跟 Codex 聊
- 链接打开方式优先在飞书内打开，才能在侧边栏用
- **多维表格**：字段（文本、单选、多选、附件、数字、进度条、电话、地理位置）、自动化、仪表盘。表单视图开分享链接，等于免费版问卷星。仪表盘可拖饼图、指标卡、词云、漏斗，换主题、上传封面，相当于手搓一个管理小站
- 机器人背后本质仍是知识库加 Skill。老师自己用极简原则：一个机器人连上 Codex，再让 Codex 调本地 Claude Code 或 WorkBuddy

飞书接 Codex，老师用的是「张咋拉」那套开源（群里发过），不是 Hermes。好处是**流式卡片**（思考过程实时输出）、多工作空间（每个 git 会话可新建仅你和机器人的群，当作独立上下文）、可交互卡片。WorkBuddy 接飞书简单得多：助理 → 设置 → 飞书集成，填 App ID / Secret，或在连接器里打开飞书 / 企微 / 钉钉。

## 十、课后问答（不挡主路径）

懂技术和懂业务哪个更重要？老师认为**懂业务更重要**。懂业务，加上 AKA，加上简单的 vibe coding，已经能解决百分之八九十的问题。专业法务顾问里，知识库和 Skill 梳理比 coding 更关键；界面只是后来加上去的壳。用客户电脑时数据不带走，是第 06 节的合规续篇。

增收不是另一套魔法。有人问：AI 似乎更适合降本提效，增收怎么做？老师的拆法是一条链路：

- **获客**：自媒体内容，用 AI 做获客内容
- **销转**：私域、客服、售前售后，让 AI 辅助
- 用在法务、财务内部，才是降本增效

刀用在哪，就是增长还是降本。自媒体获客、内容、售前售后，线下脱敏案例会走一遍；真要展开可以讲三天三夜。周末线下会带一遍沟通和方案，更细的沟通课放到下周线上。

线下还有一层目的：见面约等于面试。手头已经超过 50 个项目没人接，人才库在收。学得差不多、走一遍没大问题，就不等「彻底学完」，从项目干起。预计 8 月最后一周到 9 月初启动。企业客户从找到你，到审批、给预算、落地，快也要半个月，正常一个月、两个月。

> 真正的 FDE，它不是上个课就能学会的。……你如果没有干过一两个项目，很多隐藏知识、隐藏经历、客户的反应，很难直接教会你。

## 常见坑

- 飞书拆解稿的 AKA 和 Spec 还是空的，就丢给模型开写
- 突发奇想丢给 AI，得到 60 分 demo，越改越出新 bug，从 60 分到 90 分过不去
- 复杂任务不开计划模式，上下文窗口管理差，周额度两天烧完
- 配了 API key，选模型时没滑到「自定义模型」，仍在用套餐额度
- 任务跑着的时候用 WorkBuddy 发跟进，发不出去；要中途改方向，Codex 更合适
- Chronicle 研究预览没关，后台截图把本机数据送出去
- 飞书文档用 bot 身份创建，自己只有只读
- 相信 AI 会做 UX：合同审核做成粘贴全文，而不是上传附件
- 把 vibe coding 当标品去卖，和 WorkBuddy 说不清差别，又卖不上培训的价
