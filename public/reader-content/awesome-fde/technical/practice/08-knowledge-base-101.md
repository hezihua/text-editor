> **课程来源**：FDE 实战训练营第一期 · 第 08 节
> **时长**：约 1 小时 37 分
> **课堂文档**：飞书《FDE实战训练营第一期_技术课_简单知识库梳理搭建》
> **核心问题**：客户说「做个智能体来老带新」，你怎样从 0 搭出一套岗位级小库，而不是先搓 Agent？

今天只走「个人 / 岗位 / 部门级」能用的小库。企业级、向量库放到第 09 节。客户真实资料不能外泄，课上用模拟包带练：WorkBuddy 或 Obsidian 原理一样，要云协作就用飞书。

> 所有的这些他的需求的前提是有一套清晰完整的知识库，一套清晰完整的知识库，这个事情并不是一个简单的事情。

课上不是先打开 Obsidian 建文件夹，而是先打开一份**梳理稿**，按问题往下填。飞书文档左侧目录只有两节，这就是整节课的骨架：

1. **问题定义：客户要解决什么问题？**
2. **搭知识库，需要哪些知识？**

第二节下面才继续问：你是什么公司 → 公司做什么、有什么业务 → 哪些岗位要带新 → 这一岗怎么干活、有没有 SOP → 新人会问什么。文档写到「你的公司是做什么的？有什么业务？」就停住，后面是当场往下挖的。

## 一、课堂梳理稿（对照飞书文档填）

把这份稿当成问诊单。先填问题，再填知识；空着的格子就是还没访谈到的缺口。

### 1、问题定义：客户要解决什么问题？

| 问 | 课上模拟客户怎么答 |
| --- | --- |
| 客户要解决什么问题？ | **老带新**：老人带新人 |
| 解决方案？ | **搭知识库**（给 AI 岗位上下文；嘴上说的「智能体」本质是知识库 + Skill） |

老带新要同时做成三件事：老人时间解放，新人自己查库，入职一步一步怎么操作交给 AI。需求往往很糊——「帮我做一个智能体」不是问题定义。问题定义必须收到**一句话的业务痛点**。

### 2、搭知识库，需要哪些知识？

按飞书文档的提问顺序往下填，不要跳步。

**你是什么公司？**

> 自媒体广告带货公司

**你的公司是做什么的？有什么业务？**

再往下挖，核心往往收成一句：**品牌方广告**（短视频 / 直播里要能总结到这一句）。说不清这一句，后面的岗位和 SOP 会对不准。

**哪些岗位要老带新？**

| 岗位 | 大致职责 |
| --- | --- |
| 编导 | 选题策划、文案 |
| 拍摄 | 很多时候是助理在拍 |
| 剪辑师 | 课上完整演示的一岗 |
| 商务 | 对接品牌、报价 |
| 内容运营 | 发布、私域、评论 |

**某一个岗位到底做什么？手头有没有 SOP？**

只选一岗走到底。课上选的是**剪辑**。没有 SOP 就记「缺」，这就是后面要补、要录音、要加钱的地方。

**新人入职最常问什么？**

这一格叫**问题集**，是最重要的一块。库不是先堆手册，是先堆「新人会问、老人懒得再讲」的那些题。

填完这张稿，才知道库里该放什么。没有问题盘点，就不知道目录怎么切。

## 二、技术地图（操作版）

梳理稿填完，再认门牌。不在这节课上完本体论。

| 层 | 做什么 | 这节走到哪 |
| --- | --- | --- |
| 地基 | 目录分类、标签、元数据（来源、时长、链接、字数） | 要做 |
| 文本 | 统一成 Markdown，方便模型读 | 要做 |
| 关联 | Wiki 双向链接、MOC 导航 | 要做 |
| 检索 | 关键词（软件和 Agent 几乎自带）→ RAG / 混合检索 | 小库通常还用不上 |
| 更深层 | 知识图谱、本体论 | 明确不做 |

装了知识库软件，关键词检索一般就有。库在百万上下文以内、文档量例如 1 万篇以内，飞书或 Obsidian 往往够用。权限分级从第一天就要想。课上还提醒：不要把客户资料整包搬到自己电脑——接第 06 节，在客户工作电脑上做。

## 三、剪辑岗：把梳理稿填到参数级

演示只完整走了这一岗。前面两问（什么公司、做什么业务）填完之后，这一岗要把「流程 / SOP / 问题集」写到能交给新人执行。

**工作流程（普通公司版）：**

1. **素材管理**：归类、整理、重命名。专业公司会精细到：`2026.08.09_ARO_探店VLOG_01`（日期、ARO/BRO 素材类型、成片名、第几段）。影视飓风那一类会把命名管到这个粒度
2. **粗剪**：口播去气口、素材初步整理、时间线、出样片
3. **精剪**：特效、滤镜、音效、转场

**SOP 不是形容词，是参数。** 课上展示的切片类剪辑手册，逐步是：

- 画面：素材上轨道 → 加安全区 → 亮度提到 20 → 画面比例放大到约 105%
- 脚本：剪映智能剪口播，去掉忌口、口癖、重复词
- 音频：响度统一；人声美化看情况
- 字幕：用**系统字体**。剪映里不少字体写着可商用，实际可能仅限抖音；发到视频号、小红书有侵权风险，宁可简单
- 标题：位置、字号 13、行间距、勾选阴影；黄色色值课上写的是 `FFDE00`，阴影白色、不透明度 45、距离 10

**问题集（新人真会问的）：**

| 新人问题 | 库里该有的答案 |
| --- | --- |
| 公司素材在哪里？ | 例如剪辑专用电脑 D 盘某某文件夹 |
| 常用剪辑格式和参数是什么？ | 上面那套字号、色值、阴影——这就是行业 know-how |
| 粗剪之后初稿谁来审核？ | 对接人，课上随口起的名字是「王大强」 |

开会时对方一开始回答，你就全程录音，回来再整理。残缺库里可能只有「剪辑 SOP 第一版」，命名规则、审片人、修改次数都没定义——这就是要补的知识。

## 四、现场真实情况：不是没库，就是烂库

去企业一定会碰到：

| 现状 | 具体长什么样 |
| --- | --- |
| 没有 | 从零梳理 |
| 有但过期 | 24 年、25 年、今年 2 月、5 月各一版产品手册；刊例每年价格不一样 |
| 有但重复 | 私域小号运营手册，23 年那套到 25 年一定不适用，还叠了好几份重复 SOP |
| 有录音就算好 | 会议纪要、回放在，但没有前因后果，不知道哪段重要 |
| 扫描件 | OCR 带错字 |

有库有时候更地狱：乱七八糟，比从零还恶心。

### 补齐、清洗、核对、挖脑子

1. **补齐**：缺的 SOP 约同事重写；写不动就拉着录音，转写再提炼
2. **清洗**：格式统一成 Markdown，这一步可以交给 AI（WorkBuddy 专家技能里搜 Markdown，课上用的是把资料转 MD、信息完整无遗漏、存到指定飞书库）
3. **核对**：业务逻辑必须面对面跟业务人员过；标准、格式、重点找负责人签字式反馈
4. **挖脑子**：老员工至少半小时，常见是一个下午不够、好几个下午

> 梳理业务逻辑是你要面对面去跟着他的业务人员去做的。

签单时就要写清分工：手册由客户内部提供，你负责结构、清洗和装库。想从 0 到 1 全包，很难成交也很难交付。客户实在没时间、要你来写，前提是先开会对齐板块、用途、结构，然后**多收钱**——有公司专门靠知识库整理赚钱。

访谈提纲可以丢给 AI：把残缺库 + 剪辑 SOP 给它，说「我马上采访剪辑师，列出还缺什么」。更好的配置是：**懂 AI 的行业顾问**（资深剪辑师）拿着提纲问。纯访谈 Skill 让对方自己和 AI 聊，老师团队试过——质量没保证，旁边没人盯他就不好好问。面对面才能挖出潜在知识。客户愿意付钱，往往是他自己不愿意做或做不了。

## 五、装库顺序

```
盘点问题与手头资料
        ↓ 补齐 / 去重 / 访谈
      Markdown 清洗
        ↓
    目录分类（这节建议按岗位）
        ↓
  Wiki 双向链接 + MOC 导航
        ↓
   检索测试题（简单库 10 题，完整项目常要 30～50 题）
        ↓
  答不出 → 回去补人、补库（可能跟 3～6 个月）
```

### 1. 元数据不要洗丢

清洗时把「账本封面」留下。课上用播客《无人知晓》第 45 期举例：标题、来源（小宇宙）、节目名、期数、对话人（梦妍、李继刚）、链接、约 65 万字 / 200 多分钟、标签。原文也是元数据的一部分。

飞书云文档本身就吃 Markdown：`#` 一级标题、`##` 二级、反向引用就是 Wiki link，还有文档关系图，效果接近本地 Obsidian。PPT 可以先转成文档再入库。

### 2. 目录跟需求走，没有万能树

个人库老师用过四区：**原料区、总结区、消化区、输出区**。这家广告公司要解决的是岗位老带新，就**按岗位切**：

- 剪辑 / 运营 / 编导各一个大目录
- 剪辑下面再拆：切片剪辑、Vlog 剪辑、IP 视频剪辑；素材管理可以单独子文件夹
- 运营下面再拆：私域、短视频（评论区、转发）

**MOC（Map of Content）** 是给人导航的目录页，也给 Agent 一个入口文件。它可以按主题索引，而不是只按文件夹。老师写 AI 博主时，把新智元、机器之心、量子位、极客公园等公众号收成一份索引，再按 Cloud Code、Harness、龙虾、Skill、提示词、MCP、AI 编程、RAG 分主题——本质就是目录。另建「检索测试」文件夹，用真实问题回归。

### 3. 数据库：建表、填表、核对

中小公司三个动作：定表头（字段、关系、函数）→ 填表 → 核对。选题管理系统课上列过的字段包括：发布日期、体裁（文章 / 短视频 / 图文 / 长视频）、紧急程度、内容进度（灵感 → 选题池 → 大纲 → 初稿 → 发布 / 作废）、选题类型、难度周期、目标受众、目的（曝光 / 信任 / 私域）。

**脏表**：记录乱、重复、缺字段、前后矛盾。处理办法不是让模型凭空造数：

1. 拉负责人确认「现在最新标准是什么」
2. 重新定表头
3. 把旧表丢给 WorkBuddy，让它列出冲突点
4. 人肉逐条核对——这就是 FDE 在的理由
5. 确认过的新数据再填进去

表格清洗的第一件事是**统一标准**。每家公司表头都不一样，先定样表，规定每个字段的格式和内容，再往里灌历史 Excel。有规律就写清「以哪张表、哪个时间为准」；没规律就一条条告诉它。先填 10 行做小范围测试，对了再批量。Skill 里可以带填表脚本。

> 让 AI 填表不难，难的是如何设计梳理出一个能包含所有信息的表头结构。

完全交给模型（哪怕 GPT、Codex）「丢一堆数据自动处理好」，老师试过，总是不尽如人意。需求清晰才能干活。

## 六、测完才会发现库没搭完

课上测过一道很具体的题：**报价折扣超过 10% 时谁来审批？报价有效期多久？** 角色职责文档只写到「项目经理」，答不清。飞书自带知识问答有时也蠢，库里有都搜不出；WorkBuddy 接了飞书 CLI 反而能找到。答不出就回去问商务负责人，补进「产品与报价规则」：超出折扣必须由商务负责人审批、有效期 15 天、不要随口报总价。

可以做「知识库自动补全」Skill：人把正确答案说一遍，它识别后写入对应表。一个岗位快的三个月、常见 3～6 个月，才能摸清需要哪些知识。搭完不是结束，可能还要跟着半个月、一个月收新问题再更新。

### 动态更新怎么做

- 人少可以专人维护；人多必须各岗位自己维护，否则会像有 AI 部门的公司一样，所有人把库和 Skill 往一个部门推
- KPI 里加一条：本月是否完成知识库检查和更新
- 过时内容放进「冷藏 / 过时」目录，不参与问答；在知识库管理 Skill 或 Agent 的说明里写死：不要索引这个目录
- 文件名用 V1 / V2，Skill 里要求以最新创建时间为准
- 飞书自带历史记录（本质接近 Git）；本地 Obsidian 就单独加 log

## 七、企业库的三条主线（问答里收口）

很难给每家公司一棵万能目录树，但企业知识库至少三块：

| 板块 | 装什么 |
| --- | --- |
| 客户 | CRM：谁掏钱、为什么掏、画像、观望 / 下单 / 复购 |
| 产品 | SKU、规格；制造业后面还有库存、物流、供应链，才谈到 ERP |
| 岗位 | SOP：这岗第一步做什么、第二步做什么 |

先把这三块搭完，再谈自动化和 Skill。说明书已经有清晰目录时，仍先看需求：问题是岗位问题，就按岗位再切一刀，不够再加 MOC。

产品说明书直接丢给 AI，问产品 A 却答成产品 B：库不大时（课上口径：不超过十万篇、或不超过百万字），关键词检索按理能搜到；库非常庞大再上 RAG。知识图谱太重——团队里做 RAG 的老师说，字节 2024 年就知道图谱，至今没做，因为太重。

## 八、收费、分工和作业

按量级或按时间收：例如约定 1 万篇，超出另算。一般不单独卖「把全公司库搭完」，只做**必要知识库**。内部推不动，是因为惰性、推责，以及员工工作量已经拉满、不愿再加治理；外请 FDE 本质是借外力推动——课上说这就是 AI 时代的管理咨询加技术落地。

**当天作业：** 选一个业务问题，搭一套库，准备 **10 个问题**做检索测试；让 AI 把库 + 问答打包，传到群问卷。没有真实业务就用自己日常工作，脱敏后再交。实在没有，老师后来定了统一题：**杭州导游知识库**（景点 + 地铁 / 公交 / 打车，做规划）。第 09 节会按这题手把手再走一遍。

## 九、课上带练时的具体操作顺序

模拟包在附件里，分「残缺版」和后续完整版。跟着做时，顺序可以写成检查单：

1. 在飞书建一个仅用于课堂 / 项目的知识库文件夹（本地则新建 Obsidian 库）。权限先开到可下载、可搜索、可阅读
2. 把残缺版资料拖进去——这就是客户「已经给不了更多」的起点
3. 使用治理顾问提示词（课上原句大意）：你是企业知识库的治理顾问；目标是新人入职后能直接提问；请盘点手头资料还缺什么。把残缺库文件夹丢进对话框
4. 模型列出的缺口，对照你对业务的理解，约业务负责人或 HR 开会。老带新经常是 HR 的事，对接人找错，后面全是空转
5. 打开梳理稿，按文档顺序访谈并录音：客户要解决什么问题 → 解决方案是不是搭库 → 你是什么公司 → 公司做什么、有什么业务 → 哪些岗位要带新 → 某一岗的 1、2、3 步 → 有没有 SOP → 新人会问什么
6. 缺手册就补：约人重写，或录音转写。参数级 SOP（字号、色值、路径、对接人）比「认真负责」有用
7. 资料格式不一（MD / PDF / 图）时，用 Markdown Skill 批量转写，要求信息完整无遗漏，存回指定库
8. 按岗位建目录，再写 MOC；需要结构化的就另建模版表头，脏表只列冲突、由人确认
9. 用 10 道真问题测。飞书自带问答搜不到时，换接了飞书 CLI 的 WorkBuddy 再测一遍，避免误判「库里没有」
10. 答不出的题回到负责人补一句，再决定是手写进库，还是做自动补全 Skill

> 真正难的是你前面怎么样跟他去访谈？怎么样去把他业务逻辑给梳理出来？

提示词在有完整库之后会突然变简单，因为上下文已经在。FDE 收钱收的是访谈、分工和核对，不是最后那句「根据知识库回答」。

按文档量报价时，先约定「必要知识库」的范围和篇数，超出另算；不要承诺把公司历史上所有过期手册都治理完。电子表格已经算谢天谢地——很多现场连 Excel 都没有，那才是地狱难度。

主路径永远是：**问题清单 → 资料补齐 → MD → 目录 / 链接 → 检索测试 → 必要时再上 RAG。**

## 常见坑

- 客户说要智能体，你先搓 Agent，库还是糊的
- 跳过梳理稿，一上来建文件夹、转 Markdown
- 只收扫描件和过期 PPT，不补 SOP、不挖老员工
- 合同没写清「手册谁提供」，最后变成你从 0 写全书
- 清洗只转文字，元数据（来源、日期、版本）丢光
- 目录按自己的个人四区去套岗位问题
- 脏表让模型补全空字段，不跟人核对
